# QW buddy 架构设计（v1 定稿）

本文件是 QW buddy 的架构真相。决策理由见 [`DECISIONS.md`](DECISIONS.md)，独立审核见 [`reviews/2026-09-15-astra-review.md`](reviews/2026-09-15-astra-review.md)。

---

## 0. 一句话

**装进单个项目的「AI 主控说明书 + 几个脚本」：使用者只提需求，其余（判断、派发、盯、验收、落地、记账）全部自动。**

## 1. 命名与形态

| 项 | 内容 |
|---|---|
| 全称 | `qonnwolf-buddy` |
| 简称 | **QW buddy**（人读场合）／`qwbuddy`（机器场合：目录、命令、文件名） |
| 形态 | **不是独立软件**：一份说明书 + 几个 shell 脚本 + markdown 账本 |
| 母本仓 | `qonnwolfbuddy`——存模板、脚本、安装器 |
| 安装 | 在目标项目里执行 `qwbuddy init`（复制模板 + 建账本 + 写钩子） |
| 启动 | 在项目里开 Claude Code / Pi / Codex，说「**你现在是 QW buddy**」→ 读 `qwbuddy/QWBUDDY.md` 变身主控 |

## 2. 三层责任

| 层 | 谁保证它活着 | 状态归谁 | 备注 |
|---|---|---|---|
| **执行层**（工人，跑在 Herdr 窗口里） | **Herdr**：进程常驻，一直跑到成功或失败 | 工人自己往主账本写状态行 | 不需要盯——这是 Herdr 的核心好处 |
| **主控**（AI 会话：Claude Code / Pi / Codex） | **无保证**：会话可能结束、进程可能退出、随时可换人 | **主控无状态**——全部状态在账本；换任何 AI 读账本都能接手 | 唯一的脆弱环节 |
| **运行时**（shell 脚本） | 使用者（无守护进程） | 无状态，只读写账本 | 见到第 4 节 |

## 3. 四大机制

### 3.1 记忆
| 件 | 位置 | 说明 |
|---|---|---|
| 账本 | `<项目根>/tasks/` | 唯一真相。日期命名的任务书 + 结果 + 索引 |
| 错题本 | `<项目根>/tasks/lessons/`（索引 `lessons.md`） | 两级：索引一行 + 详情一文件（现象 / 根因 / 对策） |
| 偏好本 | 主控说明书内 | 使用者偏好与项目约定 |

### 3.2 规矩
- **施工单**：主控把需求写成任务书文件（`tasks/YYYY-MM-DD-<主题>.md`），工人读文件干活。
  **所有任务都经文件派发，无隐性依赖**——换会话、换 AI、重启都不丢。
- **隔离干活**：`herdr worktree create` 开一次性副本，代码改动只在副本里。
  **worktree 规范（四步 + 两条补充）**：
  - **开**：只在派工时开；`<项目>/.worktrees/<任务id>/`，一任务一个；开之前**先清点**——有已完成任务的残留就先收掉。
  - **收·成功**：验收通过 → 合并 / 推送 → `git worktree remove` + `git branch -d` → 记账。
  - **收·废弃**：先提交到该分支 → `git tag archive/<任务id>` → `git worktree remove` + `git branch -D` → 记账（写明已归档及标签名）。
    **为什么**：这样废弃的工作不会丢（一个标签就能找回），也不再占目录和分支——比「一律不许删」更实用。
  - **留·例外**：只允许两种——① 等使用者裁决的；② 有冲突待解的。且必须**点名**（账本一行），不得默默留下。
  - **归属**：谁派生谁收尾——主控收尾它派给工人的 worktree。
  - **补**：`git worktree prune` 清「目录已删但 git 还记着」的元数据残留。
- **验货门**：**不采信工人自述**。验收由主控独立跑项目自己的检查命令（typecheck / test 等），并把「跑了什么、结果、结论」写进账本留痕——**权力下放 + 可审计**。
- **主控可自干小活**（改动一行这类、无独立验收价值的），同样要留一行「怎么验证的」。

### 3.3 保险
- 精简版两条：**护栏**（不许改白名单外文件）、**锁**（防两个主控同时动手）。

### 3.4 运行时——唤醒主控机制（核心）
见第 4 节。

## 4. 唤醒主控机制

**目的**：主控回合结束就不回来了；需要有人把它叫醒，让它接着验收、派下一步。**全程不打扰使用者。**

### 4.1 形态

```
【主控】常驻一个 Herdr 窗口（Claude Code / Pi / Codex），空闲时不烧 token
【值守】另一个窗口跑 qwb-wake.sh（纯 shell，约 60 行）
【动作】事件或超时 → 检查账本未结项 → 有 → 叫醒主控
```

### 4.2 事件来源（全部 Herdr 原生）

| 等待 | 命令 | 说明 |
|---|---|---|
| 工人完成 | `herdr agent wait <工人窗口>` | 等会话状态变化 |
| 工人写了完成状态行 | `herdr pane wait-output --match "done:"` | 更精确的信号 |
| 兜底 | `--timeout <毫秒>` | **Herdr 超时单位是毫秒**，如 30 分钟写 `1800000` |

### 4.3 以「未结项」为准，而不是一次性通知（审核修正 ②）

值守循环**不能**是「事件发生 → 通知一次」——那样主控忙、投递失败、值守重启都会丢事。正确做法：

```
循环：
  事件 或 超时
  → 读账本，列出「未结项」（未验收 / 未处理 / 工人退出但无结论）
  → 有未结项 → herdr agent prompt <主控窗口> "看账本"
     （同一项不重复叫，直到主控把处理结果写进账本）
  → 无未结项 → 继续等
```

- **不需要队列、不需要 ACK 协议、不需要数据库**——账本自己承担这个职责。
- **工人退出 ≠ 完成**：退出但账本里没有结论的，仍算未结项。

### 4.4 两条硬约束（审核修正）

1. `herdr agent wait` 等的是**会话状态**，**不等于验收成功**——**验收必须主控自己跑检查并写结论**，不能据此销账。
2. **叫醒 ≠ 通知使用者**：唯一的动作是 `herdr agent prompt` 到主控窗口。任何「叫醒使用者」的通道（钉钉、系统通知、弹窗）**一律不要**。

## 5. 账本（唯一真相，路径唯一）

**审核修正 ①：账本路径必须唯一，且工人与主控共读同一本。**

| 项 | 规定 |
|---|---|
| 位置 | **`<项目根>/tasks/`**（沿用现有习惯，唯一） |
| 工人 | 派发时给它**主账本的绝对路径**；工人**只往主账本追加自己的结果 / 状态行** |
| 工人的代码改动 | **一律留在隔离副本里**，不写主账本所在目录的代码 |
| 主控 | 维护索引；写验收结论；写「怎么验证的」 |
| 为什么 | 工人在副本里干活，写进副本的 `tasks/` 主控在主目录**看不到**；只有绝对路径写主账本才能保证「工人完成 → 主控看得到」 |

状态行约定（工人写，主控读）：

```
working: <进展>
done: <结果 + 证据（跑了什么检查、结果如何）>
blocked: <卡在哪，需要什么>
needs-decision: <需要判断的选项>
```

## 6. 身份切换机制

**角色 = 一份独立说明书文件；切换 = 一句话；产出物标注角色。**

```
qwbuddy/roles/
├── 主控.md     立场：派发与验收；禁止：自己写实现（小活除外）
├── 审核者.md   立场：只挑错、不提方案；禁止：改代码
├── 执行者.md   立场：只干票内的事；禁止：扩大范围、改白名单外文件
└── 咨询师.md   立场：只给判断和建议；禁止：派活、改代码
```

每个角色文件写三样：**立场 / 产出物 / 禁止事项**。

切换方式：说「切到审核者」→ 读该角色文件 → **明确声明当前身份**。

**性质与限制（审核认定）**：
- 身份切换**只是行为约定**，不是权限隔离，也不清空上下文；
- 根级说明书（`QWBUDDY.md`）的固定禁令不允许被角色文件推翻；
- **同一会话换角色 ≠ 独立审核**——所以「审核必须换模型家族」这条硬规矩保留；
- **不单独记切换流水**：产出物与验收记录里标明角色即可。

## 7. 工人表 + 派工规则

### 7.1 工人（MVP 只支持三家）

| 工人 | 启动 | 能力档 | 擅长 |
|---|---|---|---|
| codex | `codex` | 强实现 | 复杂代码、重构 |
| pi | `pi` | 快速 / 便宜 | 常规执行、机械改动、调研 |
| claude | `claude` | 难活 / 审核 | 架构判断、对抗审查、前端 |

**硬限制：工人一律在 Herdr 窗口里交互式运行，禁用 headless 模式**（使用者要看得见运行情况）。加一个新工人 = 工人表加一行。

### 7.2 派工规则（自然语言，写进 config）

- 复杂架构 / 高风险改动 → 强档（codex / claude）
- 常规实现 / 机械改动 → 快档（pi）
- 审核、挑错 → **必须换一个模型家族**（不能自己审自己）
- 实时信息、联网 → 按能力表挑

### 7.3 额度判定

派工前查一次本机额度（`quota-axi`，覆盖本机已登录渠道）。**模型判定 = 智力档（活需要多聪明）× 额度现状（谁还有余量）**。

额度只是**派发时的参考**，不保证执行一定成功。

## 9. 一次完整流转

```
【使用者】提需求（说一句）
   ↓
【主控】写任务书 tasks/<日期>-<主题>.md
        herdr worktree create（隔离副本）
        herdr tab create + rename（中文标签）
        herdr agent start（工人）
        herdr agent prompt（送任务书 + 主账本绝对路径）
        账本记：任务、窗口、派发时间、状态=running
   ↓
【工人】在 Herdr 窗口里自主跑到成功或失败
        每阶段往主账本追加状态行（worker 只追加，不改别人的行）
   ↓
【值守】herdr agent wait / pane wait-output / 超时
        → 查账本未结项 → 有 → herdr agent prompt 主控窗口 "看账本"
   ↓
【主控】被叫醒 → 读账本
        → 跑验货门（项目自己的检查命令）
        → 写结论 + 证据到账本
        → 通过 → 落地（合并副本分支）；不通过 → 返工或记错题
        → 派下一步；或回空闲
   ↓
【使用者】随时问「怎么样了」→ qwb-status.sh 读账本 + 问 Herdr → 汇报
          （不会被任何通知打扰）
```

## 10. MVP 边界（明确不保证什么）

**边界选择 A（使用者已确认）**：

- ✅ 保证：**存活且空闲的主控**能被唤醒并继续处理账本。
- ❌ 不保证：**主控进程已退出 / 整机重启**后自动恢复。这种情况由**使用者重新启动主控**，主控开局第一件事读账本、从账本续接。
- ❌ 不保证：值守脚本自己长期存活——它由使用者启动（或一条开机命令）。
- 说明：不做「自动拉起主控」，因为那需要守护进程 + 会话恢复，属于重机械，与 MVP 冲突。

## 11. 明确不做

| 不做 | 原因 |
|---|---|
| 项目注册表、克隆同步、上游同步 | 单项目不需要——它自己就是项目 |
| 多机 secondmate | 单机单项目 |
| 常驻哨兵 / cron / 定时轮询 | 单人项目无场景（Herdr 事件替代轮询） |
| 对外通道（公开应答 / 语音 / 链路追踪） | 不要 |
| 自更新、子代理副意识、各家产品钩子插件 | 运行时搬出 AI 后不需要 |
| **任何通知使用者的通道** | 使用者睡觉不想被打扰 |
| 唤醒队列 + ACK 协议 + 数据库 | 账本承担该职责 |
| no-mistakes 全流水线 | 改用项目自己的检查命令 |
| 其他终端后端（tmux / zellij / orca / cmux） | 只用 Herdr |
| 角色切换流水账 | 产出物标角色即可（审核建议砍） |

## 12. 两条判断尺子

1. **谁的状态**：状态属于**产品**（会话 / 模型 / 厂商）→ 交给那个产品；属于**使用者和项目**（任务 / 验收 / 教训）→ 放在产品外面，也就是 QW buddy 这层。
2. **薄即抗淘汰**：Harness（Claude Code / Codex / Pi）会越来越强，会吃掉「等待、通知、记忆」这类事；QW buddy 只持有它吃不掉的东西——**跨厂商调度 + 属于项目的账本与验收纪律**。
