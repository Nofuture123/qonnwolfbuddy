### R2-M1【必须补】再次派发会把改坏的验收场景重新认作冻结基线

**位置**：`bin/qwb-run.sh:94–106,168–175`；`bin/qwb-lint.sh:149–173`。承诺：`templates/QWBUDDY.md:78`、`docs/DESIGN.md:214`。

当前 run 不比较已有 `scenarios-fp:`，直接计算当前内容并覆盖原指纹。因此正常的“返工后再派发”入口就能抹掉冻结证据，无需手算或伪造 hash。

**独立最小复现**（安装项目声明好双门；Herdr 为替身）：

1. 合法任务含 `Then seed returned` 和一条失败场景，`qwb-run.sh ... --here` → rc=0、写入指纹。
2. 将该行改成 `Then broken returned`，lint → rc=1，明确报“验收场景在派发后被改动”。
3. 对同一任务再次执行 run → rc=0。
4. 再跑 lint → **rc=0、LINT PASS**；原基线已被替换。

另一个实测退化路径：修改场景后删掉 `scenarios-fp:`，保留新派发的 `dispatch:`，lint 也 rc=0，只提示“旧制派发，无冻结基线”。目前“旧任务豁免”没有区分旧任务和新任务丢失基线。

这不是要求密码学防篡改；问题是自家正常派发入口会主动消除违规证据。应在再次派发时保留并核对已有基线，明确新任务丢失基线的处理，补上“改场景 → 再派发”的负例。历史兼容不应让新派发任务静默退回无冻结状态。

### R2-M2【必须补】契约只检查路径非空，类型错误能过；运行时解析退化也不受负例约束

### R2-M4【必须补】F2 的追加断言被重复标记蒙混，真实丢行仍全门通过

**位置**：`tests/smoke.sh:764–784`；第一次 awk 调用是 `bin/qwb-run.sh:86–94` 的场景提取。

替身每次 awk 调用都追加**同一文本** `done: awk-injected-during-dispatch`；测试最后只 grep 是否存在。场景提取先调用一次 awk，早早留下该标记。后面的坏快照窗口即使吞掉第二次追加，第一次仍在，grep 还是 PASS。

反转 R2 的关键改动（仅临时副本）：

```bash
# 原来的 agent start 从记账后移到记账前
herdr agent start "$NAME" --kind "$WORKER" --pane "$PANE" --timeout "$START_MS"

# 将 state 改写退化为旧的快照覆盖窗口
awk 'BEGIN { changed=0 } /^state:/ && !changed {
  print "state: running"; changed=1; next
} { print }' "$TASK_FILE" > "$TASK_FILE.audit-snapshot"
mv "$TASK_FILE.audit-snapshot" "$TASK_FILE"
```

full 实测 rc=0；以下原断言仍全部打印 PASS：

```text
PASS  awk 快照窗口注入的追加行未丢
PASS  agent start 时工人追加的行存活
SMOKE PASS
LINT PASS
```

为排除“变体其实没丢行”，另做独立探针：每次 `/usr/bin/awk "$@"` 结束后递增外部计数，追加 `done: audit-awk-<序号>`；start 另追加 `done: start-unique`。

```text
当前实现：awk_calls=1；保留 audit-awk-1、start-unique；rc=0
坏变体：  awk_calls=2；仅保留 audit-awk-1、start-unique；rc=0
                      audit-awk-2 确实丢失
```

start 断言也未捕获此窗口，因为 start 时的追加发生在读取快照之前，已被快照包含。应使用每次唯一的注入标记，核对注入次数与所有对应行，而不是仅证明某个同名标记存在。本项判“必须补”是因为当前生产顺序已修好，坏的是防止致命问题回归的验收门；不把临时变体的丢行冒充当前生产 F2 仍未修。
