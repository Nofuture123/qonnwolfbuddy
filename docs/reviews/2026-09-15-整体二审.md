## 审点 1：目标与实现自洽

### F1【致命】工人无状态行便挂起/退出后，主控没有超时回来的路径

**位置**：`bin/qwb-wake.sh:73–94,132–165`；承诺见 `docs/DESIGN.md:91–107,251–254`、`docs/DECISIONS.md:73–77`。

合法时间线：工人写 `working:` → 值守叫醒一次 → 主控发现仍在运行，结束当前回合 → 工人因进程退出、额度/网络问题或卡住而没有追加终态行。主控仍存活且空闲，值守也仍存活。

指纹仅包含 `state` 和最后一条状态行；`wake:` 的时间戳不参与是否需要再叫的判断。`agent wait` 的成功、失败、超时只影响补睡，不改变唤醒资格。之后每轮都因同一指纹 `continue`。因而文档所说的「工人退出但账本无结论仍算未结项」在此只剩清单分类，无法把超时判断交回主控。它违反核心目标，不属于「主控已退出不自动拉起」这一 MVP 豁免。

**独立复现**：临时任务含 `state: running`、`working: running`、一条时间为 `2000-01-01T00:00:00Z` 的 dispatch。运行原始 `qwb-wake.sh --interval 1000`；Bash 函数替身使 `pane run` 成功、每次 `agent wait` 返回 1；sleep 替身在第三次调用时结束实验。原始输出：

```text
已叫醒：2099-01-01-silent.md state=running → pane fake:controller
跳过：2099-01-01-silent.md state=running（已叫过，进展未变）
跳过：2099-01-01-silent.md state=running（已叫过，进展未变）
FAKE_LOOP_END wakes=1 waits=3 sleeps=3
```

独立 `--once` 实验同样连续两次跳过；追加一条 `done:` 后立即又叫一次，证明触发条件确为账本行变化。三轮是实测，「无新行则永久跳过」由不含时间/工人状态的分支推导；未声称真实等待多年或实测了真实工人崩溃。

### F2【致命】派发记账可静默抹掉工人刚追加的结果和证据

**位置**：`bin/qwb-run.sh:123–137`；共享追加约定见 `templates/QWBUDDY.md:35–37`、`docs/DESIGN.md:120–124`。

脚本先启动工人并提交提示词，再把整份任务书复制到固定临时文件、修改 state，最后 `mv` 覆盖原文件。工人此时被明确允许往主任务书追加进展。若追加发生在复制读完之后、`mv` 之前，追加行被旧快照替换掉；派发仍退出 0 并宣告成功。主控目录锁不约束工人的合法追加，因此不能保护这个窗口。若丢的是唯一 `done:`/`blocked:`，账本证据消失，值守也可能再无新信号。

**确定性复现（Herdr 与调度时点均为替身）**：临时安装后创建含 `state: running` 的任务。正常执行原脚本，导出以下两个 Bash 函数；`AUDIT_LEDGER` 指向该临时任务的绝对路径：

```bash
herdr() {
  case "$1 $2" in
    "tab create") printf '%s\n' '{"result":{"root_pane":{"pane_id":"fake:p1"}}}';;
  esac
}
awk() {
  command awk "$@"
  printf '%s\n' 'done: concurrent worker result; independent-check exit=0' >> "$AUDIT_LEDGER"
  printf '%s\n' 'PROBE: worker done appended after awk copied task, before mv' >&2
}
export -f herdr awk
# 用该环境运行原 bin/qwb-run.sh --project "$P" --task ledger-race --worker codex
```

实测派发 rc=0，注入标记已输出；最终任务只有原 `state`、`working` 和新 `dispatch`，`HAS_DONE False`。这证明一个可达交错会丢行；没有把函数注入说成自然调度下的发生概率，也没有修改源码复现。

### 已核对且未发现问题的边界

- 身份切换明确只是行为约定，四份角色文件均存在并服从根级禁令；对此未发现缺件。
- 派工规则明确使用自然语言，不要求自动推理路由器；`QWB_WORKERS` 的整词选择校验存在。未把未实现自动模型选择当成新缺陷。
- 唤醒实际通过 `herdr pane run`；启动通过 `herdr agent start ... --kind ... --pane ...`，没有 headless 参数。本机 `herdr agent` 帮助确认这些接口存在。完整跨 CLI 行为仍未在本轮实测。
- 未发现新增的人类通知通道或被禁止的基础设施。不要求守护进程、ACK 或自动复活主控。

## 审点 2：测试纪律是机制还是说法

### M1【必须补】场景存在、失败路径和冻结均没有执行门

**位置**：`templates/QWBUDDY.md:74–78`、`templates/TASK.md:17–33`；实际检查为 `tests/smoke.sh:553–564`；派发路径 `bin/qwb-run.sh:44–139`；承诺见 `docs/DECISIONS.md:258–266`。

smoke 只 grep 模板含 Given/When/Then、失败路径、场景冻结等词，不读取被派发任务的场景，不检查冻结前后变化。run 只定位任务文件，不要求场景；lint 的四项也没有这些检查。提交实现之前是否已有定稿，以及实现后是否改场景，没有任何基线或执行检查。这里不能把「模板存在」算成「规范受约束」。

**独立复现**：在刚安装的临时项目里创建仅一行 `state: running` 的任务，Herdr 使用 F2 中的响应函数替身但不注入 awk。`qwb-run.sh --task audit --worker codex` rc=0、有 `dispatch:`；`qwb-lint.sh --project "$P"` 四项 PASS、rc=0。正常场景和失败场景均为零条。现有 smoke 自己也在 `119–123` 行用无场景任务断言派发成功。任务书强制性、失败路径下限和冻结是同一个机制缺口，本报告合计一个发现。

### M2【必须补】fixture 检查不是 JSON 路径契约，结构错位仍全门通过

**位置**：`tests/smoke.sh:70–91,588–609`、`bin/qwb-run.sh:113–117`；承诺见 `docs/DECISIONS.md:263,270`。

`tab-create` 的所谓 `.result.root_pane.pane_id` 断言只是分别 grep 三个字段名；运行时也从整段输出用正则取任意 `pane_id`。其余多个样本仅查 `"result"` 字面量，没有验证相应类型或层级。fixture 的历史注释也不构成对当前依赖的自动校验；调度调用使用固定样本，CLI 形状变化不会自动更新样本。

**独立变异实验**：将 `bin/`、`templates/`、`tests/`、`qwb.config.sh` 复制到临时母本副本，仅把 `tests/fixtures/herdr/tab-create.json` 改为以下合法 JSON：

```json
{"result":{},"root_pane":{},"pane_id":"fake:p1"}
```

该 JSON 完全没有 `.result.root_pane.pane_id`。在副本运行 `bash bin/qwb-test.sh full`，9.243 秒、rc=0，仍打印：

```text
PASS  tab-create fixture 含 .result.root_pane.pane_id 契约字段
PASS  改 fixture 后派发 pane 跟着变（stub 真读 fixture，非硬编码）
SMOKE PASS
LINT PASS
```

因此不能据此宣称「herdr 换字段形状也能挡住」。删除所有 `pane_id` 字面量确实可能被当前门抓到，读 fixture 也确有生效；问题是效果远窄于声明。该实验是契约负例，不声称真实 Herdr 0.8.2 正在返回这个错误结构。

### M3【必须补】lint 有真实拒绝能力，但 state、死键和扫描范围存在直接漏检

**位置**：`bin/qwb-lint.sh:50–60,62–76,79–94,97–104`；声明见该脚本 `9–16` 行、`tasks/2026-09-15-qwbuddy吸收-测试纪律.md:114–117`。

在临时安装项目中，分别构造反例，运行原始 lint：

| 检查 | 本轮反例与实际结果 | 判定 |
|---|---|---|
| 文档点名脚本存在 | 点名缺失的 `qwb-missing.sh` → FAIL；把已点名脚本置空 → PASS | 对字面文件存在检查未发现问题；它不证明脚本实现了承诺，置空结果不另计缺陷 |
| state 值域 | 任务内容 `state: ` → `LINT PASS`、rc=0；同一任务 wake 输出 `state= 非法…不会被叫醒` | 第 67 行把空值直接跳过，混淆了无 state 的非任务文档与有字段但无合法值的任务 |
| config 死键 | 追加未使用的 `export QWB_AUDIT_UNUSED=1` → PASS；改成普通赋值、仅在脚本注释写 `# QWB_AUDIT_UNUSED` → 仍 PASS | 提取不识别合法 export 声明；字符串出现被当成实际读取 |

反向控制：一个临时坏项目同时放入「缺失脚本、`state: pending`、普通未引用 QWB 赋值、`qwb-foo.sh` 的非 ASCII 写法」，实测四项 FAIL、rc=1。所以不是「lint 永远绿」，而是若干常规违规能无须复杂混淆就通过。这正是本轮要求怀疑的弱门问题。

### M4【必须补】快门列出了 smoke 语法检查，实际没检查它

**位置**：`qwb.config.sh:2`、`templates/config.sh:7`、`bin/qwb-test.sh:54`。

声明 `bash -n bin/*.sh tests/smoke.sh && shellcheck bin/*.sh` 中，Bash 只把第一个展开的文件当作脚本，其余作为位置参数；shellcheck 又只覆盖 bin。于是 `tests/smoke.sh` 完全不在该快门的语法检查里。

**独立复现**：在临时副本的 `tests/smoke.sh` 末尾追加 `if then`：

```text
bash -n tests/smoke.sh
rc=2; line 614: syntax error near unexpected token `then'

bash bin/qwb-test.sh fast
rc=0; stdout/stderr 均为空
```

这不是要求快门跑全量行为测试，而是它自己声明的语法检查没有执行到指定文件。

## 审点 3：整装可用性

### M5【必须补】母本与安装版入口混用，默认整装有真实断点

**位置**：`README.md:5`、`docs/DESIGN.md:19,201–208`、`templates/QWBUDDY.md:99–110`、`templates/config.sh:6–8`、`bin/qwb-init.sh:24–27,29–48`、`bin/qwb-test.sh:41–62`。

在一个不是本仓的空白目录执行以下链路（`SRC` 为审核对象母本根、`P` 为临时空白目录）：

```text
cd /tmp
bash "$SRC/bin/qwb-init.sh" "$P"
rc=0，安装完成

bash "$P/qwbuddy/bin/qwb-test.sh" fast --project "$P"
rc=127，bash: bin/*.sh: No such file or directory

bash "$P/qwbuddy/bin/qwb-test.sh" full --project "$P"
rc=127，bash: tests/smoke.sh: No such file or directory
```

脚本安装在 `qwbuddy/bin`，模板却直接启用了母本 `bin`、`tests/smoke.sh` 路径；安装器也没有复制 smoke 与 fixtures。`templates/config.sh:6` 确实写了「按本项目布局调路径」，`QWBUDDY.md:78` 也要求声明项目自己的门，因此不能说完全没有配置说明。但现有值并非未配置占位，而是会被执行器直接执行的默认门；空白项目没有这些文件，失败后也不会进入「门未声明」提示。现有安装测试检查文件与变量存在，未实际跑初装默认门。

同一安装包里的 `qwb-init.sh` 被列作可用于「装进新项目」的运行时脚本，但执行 `bash "$P/qwbuddy/bin/qwb-init.sh" "$P2"`，实测 rc=1，报缺 `qwbuddy/bin/../templates` 并要求从母本仓运行。母本脚本可从任意 cwd 用绝对路径正常运行；安装版副本却不具备文档列出的用途。

此外，README/DESIGN 的 `qwbuddy init` 没有仓内命令入口、包装器或安装步骤，本机 `command -v qwbuddy` 也无结果。它不能作为当前可执行的一条命令。这三处都是母本与安装产物的入口/文件清单不一致，合计一个整装发现；没有要求把整个母本测试体系强塞进目标项目。

### M6【必须补】文档给出的默认派发命令会把工人送进主项目代码目录

**位置**：`bin/qwb-run.sh:14–17,88–126`、`templates/QWBUDDY.md:58–59,102`；约定见 `templates/QWBUDDY.md:36–37`、`templates/roles/执行者.md:7,22`、`docs/DESIGN.md:42,121–122`。

按脚本帮助及总说明书脚本表执行 `qwb-run.sh --task <id> --worker <名>`，省略两个可选 worktree 参数时，`DIR` 默认等于主项目根；tab 在该目录创建，提示词还明确说「工作目录=<主项目根>，代码改动只留在本目录」。这与工人代码一律留在隔离副本、禁止写主账本所在目录代码的约定直接冲突。

**独立复现**：本轮临时空白项目使用 Herdr 响应函数替身，运行最小派发命令，rc=0、记账 `dir=<临时项目根>`，未建立 `.worktrees`。传 `--worktree <任意存在目录>` 也只检查目录存在，不确认它是隔离副本；现有 smoke 的 `119–123` 行正使用主临时项目自身作为这个参数。

这不是要求文件权限沙箱，也不是把行为白名单当作缺陷；问题是公开的默认脚本路径主动向工人发出与总规矩相反的工作目录指令。使用正确 `--create-worktree` 的真实 Git 路径本轮已通过，不能替代这个默认路径的反例。

## 结论

**不通过：致命 2，必须补 6，可以不要 0。**

- 致命 F1：无账本新行的工人故障后，存活空闲主控可能永久不再被叫醒。
- 致命 F2：派发时整体替换任务书，会丢掉工人合法并发追加的结果与验收证据。
- 必须补 M1–M6：场景/冻结无执行门、契约结构假绿、lint 漏检、快门漏检测试语法、整装入口与默认门不自洽、默认派发违反隔离约定。

项目目标仍立得住；当前实现尚不能兑现「唤醒持续闭环 + 可审计项目账本」，也不能把 DECISIONS §21 的五条纪律标成全部机械落实。三次全门绿色只证明现有测试通过，不消除本轮独立反例。没有新增功能诉求；不重复追究已经明确接受的主控退出恢复边界或 Git 非原子收尾窗口。
