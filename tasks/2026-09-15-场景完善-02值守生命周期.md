## 目标
主控开局自己启动或复用值守；使用者不需要当启动员。值守失活可见，但不承诺主控退出或机器重启后自动复活。保持纯 shell、Herdr、账本的现有形态。

## 验收场景

### user_开局无需手工启动值守
Given 项目已安装、主控存活、尚无本项目有效值守
When 主控按开局步骤操作
Then 当前 workspace 内创建一个可见的值守 tab，记录身份，启动 qwb-wake.sh；重复开局复用而不重复创建或抢占其他项目 pane

### user_失活值守明确可见
Given 账本记录的值守已退出或 pane 仍在但其值守进程不在
When status/开局检查
Then 明确显示未运行或未知，不把“pane 存在”当健康；主控存活时可重新启动，不通知使用者、不启守护进程

### user_忙态不丢结果
Given 01 已确定当前 CLI 在主控忙时的真实投递行为
When 修订投递处理（仅在 01 证明有缺陷时）
Then 依据真实行为做最小修复，结果仍留账本；不因文字写入成功就虚报已被主控处理

### user_日志引用不成为控制指令
Given 01/定向复现证明代码围栏内的 done/spec-resolved 等文本被误认作状态
When 解析同一任务书
Then 明确区分正式状态记录与引用文本。先核对历史票把 state 写在代码围栏里的约定，不得统一“忽略所有围栏”而让现有票全部消失；有兼容方案和真实回归才收敛到共用解析入口

## 本轮落地要求（基于01，不扩新架构）

1. 提供幂等的值守确保入口（优先 qwb-wake.sh --ensure，复用原命令，不新建服务）：主控开局调用，显式目标 pane/项目；只能在调用者自身 workspace 开/复用可见 shell tab。重复调用最多一个有效实例，不杀别的 pane。识别依据须含实际项目与值守进程，不凭 pane 存在或名字相似就报存活。未知身份/无法查询时明确报错，不擅自重开多个实例。
2. status 显示本项目值守“运行/未运行/未知”，开局说明让主控先确保值守，再派活；不承诺主控已死时还能自动修复。
3. --pane 复用要在派发副作用前核对 cwd 与目标 worktree，无法确认或不一致则拒绝并给明确修复步骤；不要往未知 TUI 发 cd。首次目录 trust 是一次性项目授权/准备步骤，不自动接受任意未信任项目、不关闭全局信任规则。文档与返回信息明确“已投递≠工人已开始”，不得靠隐式补发掩盖失败。
4. 先写 user Given/When/Then 正反例，fake Herdr 只用于单测且需契约校验；主控最终用真实 Herdr 重跑确保/重复/失活检测与准备好信任后的默认闭环。没有依据的忙态投递重试、自动确认、自动重启主控全部不做。
5. 围栏/共用解析器只登记可复现证据，不在本次实施；原因：当前票头使用围栏，粗暴过滤会破坏现有协议，需单独设计后再动。

## 实现边界
优先复用现有脚本和 Herdr 查询，不凭空加 supervisor、注册中心、轮询服务、通知通道。启动身份记录只保留最低所需字段，不能把其他项目的空闲 pane 当本票所有。
围栏问题须先复现后定范围，是协议一致性修复，不做通用 Markdown 解析器。预算测试用 fake timer；真实跨 CLI 行为使用真实集成试验。
