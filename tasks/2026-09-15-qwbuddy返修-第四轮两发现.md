## H1（主控裁定：必须补，**不要**去实现不可达的「原子删除」）

**审核的指控**：`check_unchanged`（复核）与 `git worktree remove`（删除）是两次独立 Git 调用，之间仍有窗口，理论上仍可能删掉「复核之后才产生的新提交」。

**主控的裁定与理由（请照此实现，不要自行追求原子性）**：

- detached HEAD 上的新提交**不更新任何 ref**，因此「读完 HEAD → 删 worktree」之间产生的提交，**在 Git 原语层面无法被任何检查捕获**；真正根除只有「不删 worktree」一条路，而那违背「防堆积」的设计目标。所以本项**不要求**消除窗口。
- 该窗口的前置条件是**工人仍在往该副本写入**，这与收尾前提（任务已验收、工人已停）冲突；且窗口内产生的对象**不会立即消失**（dangling 对象，可 `git fsck --lost-found` 找回），不是静默清除。
- **本条我认的是「表述夸大」**：脚本输出与文档此前给人的印象是「TOCTOU 已封住」，实际是「窗口缩小到相邻两次 Git 调用之间」。

**规格（只做这三件）**：

1. **输出诚实化**：删除动作的**成功**输出里，明确带上**实际归档 / 删除时依据的 OID**，并加一句限定，例如：

```
已归档：tag archive/<任务id> → detached HEAD <OID>；worktree 已删（保留分支 …）
注意：删前复核与删除是两次 Git 调用；若收尾时该副本仍在被写入，其新提交会成为
      未引用对象（可用 `git fsck --lost-found` 找回）。收尾前提是工人已停止写入。
```

   （`--merged` 路径同样带上删除时的 OID。措辞可调整，但**必须包含**「两次 Git 调用之间有窗口」与「dangling 对象可找回」两点，不许把窗口说成已消除。）
2. **前置条件显式化到脚本**：在 `--help` 与脚本开头注释里写明——**收尾前提是该 worktree 的写入者已停止**；若无法确认，请先确认再收尾。不做任何 herdr 查询、不加锁、不加新依赖。
3. **`check_unchanged` 失败时的输出**保留现状（拒绝 + 提示重新收尾），但要**额外打印当前 OID 与原先 OID 的完整值**（便于事后比对），不要只打印短 SHA。

## H2（必须补）：等待预算在非整秒 interval 下仍会多睡一秒

**事实（审核已实测）**：`bin/qwb-wake.sh` 用 `date +%s`（秒级）计时 + `sleep "$(( remain / 1000 > 0 ? remain / 1000 : 1 ))"`（**至少 1 秒**且取整）。在 `interval=100` 时，超时路径 `dt=0` → 又补睡 1 秒，三轮耗时 2.4 秒（应约 0.3 秒）；`interval=1000` 时恰好正常，所以此前没暴露。

**规格**：

1. **`sleep` 支持小数秒**（GNU 与 BSD/macOS 的 `sleep` 都接受小数，`sleep 0.1` 合法）：把整秒取整改成按**剩余毫秒**换算的**小数秒**，例如：

```bash
sleep_remainder() {   # $1 = 剩余毫秒
  local ms="$1"
  (( ms > 0 )) || ms=1
  sleep "$( awk -v m="$ms" 'BEGIN{printf "%.3f", m/1000}' )"
}
```

   （也可用 shell 整数运算直接拼出 `秒.毫秒`，避免依赖 awk；两者都可以，只要**精度到毫秒**且**不引新依赖**。）
2. **计时精度**：秒级 `date +%s` 在非整秒 interval 下不足以判断预算。改用毫秒级计时 —— 注意 **macOS 的 `date` 不支持 `%N`**；可用 `perl -MTime::HiRes`（本机必有 perl）或 `python3`（**不要在运行时脚本里用 python3**，它只允许出现在 `tests/smoke.sh`）。若两者都不想引，替代方案：**用 `SECONDS` 变量 + 小数 sleep 的组合**，或干脆**把「剩余预算」按 `interval` 减去实际等待时间的整数秒近似**并在文档里承认秒级精度——但你必须在任务报告的 `done:` 里**明确写出你选了哪一种以及精度上限**。
3. **性质要求（验收点）**：
   - `interval=1000`：立即成功 / 立即失败 / 耗尽 timeout 三种返回下，**三轮总耗时都在 2.7–3.3 秒之间**（约 1×interval/轮）；
   - `interval=100`：三种返回下**三轮总耗时 ≤ 1.2 秒**（修复前是 2.4 秒）；
   - 不得退化成忙循环（三轮总耗时不得 < 0.15 秒）。
