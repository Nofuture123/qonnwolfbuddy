## 目标
把已要求的独立审核变成可检查的证据，不能把“不同 CLI/provider”误认成“不同模型家族”。不建动态模型注册表，不增加普通票的无用必填字段。

## 验收场景

### user_换CLI不等于独立审核
Given 实现者是 Codex 上的 GPT 系模型，审核者是 Pi 上的同家族模型
When 对已要求独立审核的票检查身份
Then 不得凭 CLI 不同报通过；报错明确指出同家族

### user_不同模型家族审核有效
Given 真实会话记录分别确认实现者和审核者的 CLI、模型与家族，且审核者不是同一会话换角色
When 核对票内证据
Then 接受其独立性元数据；不因此宣称代码审核结论必然正确

### user_身份未知不伪装通过
Given 会话缺模型信息或模型家族无法可靠判断
When 核对一个已要求独立审核的交付
Then 输出身份未确认，需要主控补证据；不凭名称猜测、不能标独立审核已完成

### user_无审核要求的普通票不额外烧token
Given 普通小票本身未要求独立审核
When 检查票格式
Then 不强制启动审核 agent、不新增模型调用，只跳过相关检查并明确范围

## 实施原则
先调查现有会话元数据能提供什么，CLI 与模型家族分开记录；如工具不能自动给出 family，由主控显式声明并附原生 session 证据。只在需要审核的票记录，已有历史票不得凭空补身份。
不提供全模型映射数据库；本轮审核过程仍最多三个审点，用用户指定或全局规定的审核模型，不强制修改 provider。

## 验证
先写上面的 user Given/When/Then 正反例；同 CLI 不同模型、不同 CLI 同家族、未知身份分别覆盖。若声明自动校验则对实际入口做反转验证，不只测文案关键词。
合并前主控独立 fast/full；一次有限审核确认映射与证据边界。真实闭环前不为这项单开研究 agent。
