## F3（致命）：工人完成后无法再次叫醒主控 —— 主控规格已重定，照新的做

**现状**：未结项判定与去重都只看任务书头部的 `state:`，而 `state:` **只有主控能改**（工人只追加状态行）。于是：第一次叫醒写下 `wake: ... state=running` 后，工人即使完成并追加 `done:`，`state` 仍是 `running`，指纹没变 → **永久跳过，主控再也不会被叫**。实测确认：`done:` 与 `blocked:` 两种行都被忽略。

**新规格（主控裁定，直接实现）**：把去重键从「state」改为「**进展指纹**」：

```
fp = sha1( state 值 + "\n" + 最后一条匹配 ^(working|done|blocked|needs-decision): 的行原文 ，无则空串 )
```

- 计算用 `printf '%s' "$X" | shasum | cut -d' ' -f1`（macOS 自带 `shasum`，不引新依赖）。
- **未结项**仍为 `state ∈ {running, blocked, needs-decision}`。
- **需要叫醒** = 未结项 且（无 `wake:` 行 **或** 最近一条 `wake:` 行的 `fp=` 与当前 `fp` 不同）。
- 叫醒后写：`wake: <ISO8601> state=<state> fp=<sha1>`。
- 兼容旧的、没有 `fp=` 的 `wake:` 行：解析不到 `fp=` 视为「指纹不同」→ 允许再叫一次（不能因此漏叫）。

效果要求（这是验收点）：同一任务书，工人追加了 `done:` 行之后，`qwb-wake.sh --dry-run` **必须**再次把它列为未结项；若之后什么都没再发生，才不再叫。

## F4（致命）：一次投递失败即终止整个值守

**现状**：`herdr pane run` 是 `set -e` 下的普通命令，返回非 0 直接退出脚本。DESIGN §4.3 明确要求「投递失败不能丢事」。

**新规格**：

- 投递（`herdr pane run`）失败时：**不写 `wake:` 行**（保持未叫状态，下轮重试）、向 stderr 打印错误、**继续处理下一个未结项**、整轮结束正常返回 0。
- 值守主循环不得因任何单次投递失败而退出。
- 加断言：stub `herdr` 返回 1 时，`qwb-wake.sh --once` 退出码必须为 0。

## F2（必须补）：值守等错 pane，且失败后忙循环

**现状**：`wait_round()` 用 `grep -h '^dispatch:' "$LEDGER"/*.md | head -1` 取 pane —— 不筛未结任务、不取最新，实测取到了**已 verified 的旧任务书**里的 pane；该 pane 失效时 `herdr agent wait` 失败被 `|| true` 吞掉，下一轮立刻重扫，形成**忙循环**（审核实测 5 轮耗时 0.072 秒）。

**新规格**：

- 只从**未结项**的任务书里取 `dispatch:` 行，取**时间戳最新**的一条。
- 该 pane 上的 `herdr agent wait --timeout <interval>` 失败（pane 已关/agent 已退）时：**不得立即重扫**，退化为按 `interval` 的等待（`sleep`）后再进入下一轮；且不得因此退出。
- 无可用 dispatch pane 时：按 `interval` 等待后重扫（这是 DESIGN §4.3 允许的「超时」兜底，不是新增轮询）。
- 加断言：构造「dispatch 指向已关闭 pane」的场景，测连续两轮 `wait_round` 的实际耗时 ≥ 一个间隔量级（例如 interval=1000ms 时两轮 ≥ 1.5s），证明**没有忙循环**。

## F1（必须补）：DESIGN 承诺的「锁」不存在

**现状**：`docs/DESIGN.md` §3.3 只写了一句「保险：护栏 + 锁（防两个主控同时动手）」，无定义、无实现。

**新规格（最小实现，不扩范围）**：

- 锁 = **目录** `<项目>/qwbuddy/.controller.lock`（`mkdir` 是原子操作，无需额外依赖），目录内写一个 `owner` 文件，内容为 `<ISO时间> <pane_id 或 pid>`。
- `qwb-run.sh` 派发前检查：无锁 → 获取（`mkdir` 成功即获得）；已有锁 → **拒绝派发**，报错说明锁主是谁、以及如何手动释放。**不要**做 `--force`/超时自动夺锁（YAGNI）。
- 新脚本 `bin/qwb-lock.sh`（`acquire` / `release` / `status` 三个子命令，各几行），供 `qwb-run.sh` 与主控开局调用。
- `qwb-init.sh` 不要预建锁目录（锁由 acquire 时创建）。
- 相应更新 `templates/QWBUDDY.md`（开局点名时抢锁）与 `templates/config.json`（`lock` 一节：路径与说明）。
