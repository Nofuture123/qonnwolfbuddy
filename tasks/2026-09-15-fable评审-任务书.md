## 一、项目目标（判断一切取舍的尺子，三句话）

QW buddy 是**装进单个项目**的「AI 主控协作层」：一份说明书 + 8 个 shell 脚本（约 1100 行）+ markdown 账本。它管的不是"一个 AI 怎么把活干好"，而是**「活本身怎么被派发、验证、记住」**：主控写任务书（票）→ 派给 Herdr 窗口里的工人 → 值守把主控叫回来 → 主控独立验收 → 记账。

三条尺子：① 谁的状态归谁（产品的状态交给产品，项目的状态留在项目外）；② **薄即抗淘汰**（Harness 会长大吃掉等待/通知/记忆，只持有它吃不掉的：跨厂商调度 + 项目账本与验收纪律）；③ **能自动检查的规范不要只写在纸上**。
硬边界：零通知使用者、无队列/ACK/数据库/守护进程/cron、只用 Herdr、纯 shell 零外部依赖。

## 二、现状（**不必重读全仓**，需要时抽查即可）

**已实现**：账本（`tasks/` 任务书 + 状态行 + 错题本）／唤醒（进展指纹去重 + **时间兜底重叫** + 投递容错 + 一轮 1×interval 等待预算 + 可注入假时钟）／派发（**验收场景门**（含至少一条失败路径）+ **场景冻结指纹** + **疑点门** + 工人名整词校验 + **默认隔离副本** + 记账先于启动）／验收（不采信自述、独立跑门、留痕）／worktree 四步（list/finish --merged|--archive|--keep，删前复核 HEAD、detached 用实际提交、`--keep` 不脏检查）／身份切换（4 份角色）／保险（mkdir 原子锁 + 护栏=行为约定）／质量门（快门/全门，未声明门报错）／`qwb-lint.sh`（6 项自身 lint）／herdr fixture 契约基线（真录 + 真实 JSON 路径与类型校验）。

**最近新增**：**疑点处置门 + 显式修订** —— 工人或主控可写 `blocked: spec-defect: <票的哪条有问题 + 反例 + 照做会错在哪>`；只有主控能写 `working: spec-resolved: <impl|spec> + 逐项回应`；`qwb-run.sh` 在未处置疑点存在时**拒绝派实现**；`--revise-scenarios=<原因>` 让改票**留痕**（旧指纹→新指纹 + 原因），无痕改场景仍失败。

**质量状态**：六轮对抗审核（Astra medium/high）累计 **致命 6 → 0**；`tests/smoke.sh` **328 项断言 / 0 FAIL**（全门 22 秒，快门 0.3 秒）；`docs/` 有 DESIGN 13 节 + DECISIONS 24 节 + 7 份审核报告 + 5 条错题本。**尚未做**：真实项目跑通一轮完整闭环（真实 herdr + 真实工人 + 值守叫醒），目前只跑过真实工人与真实 worktree，值守叫醒一直是手工调的。

## 三、要你回答的四个问题（按这个顺序，简洁）

1. **哪些判断是对的**（不该动的基础）—— 3–5 条，一条一句话。
2. **改进空间** —— 按价值排序，**最多 5 条**。每条给：位置/现状 → 建议 → 成本估计（行数或人工步骤）→ 标"必须"还是"可选"。
3. **结构性风险** —— 现在看不出来、将来会爆的，**最多 2 条**（例如某种设计取舍在第 N 个真实项目上会崩）。
4. **如果只做 1–3 件事**，做哪几件、为什么。

## 四、约束与产出要求

- **薄**：不引入守护进程/数据库/新依赖/新服务；不改「账本 + 脚本 + 换模型家族审核」这个形态。
- **成本效率**：每加一个机制都有长期 token 与认知成本——请在建议里明说"这个投入值不值"。
- **别复述背景**、别写长报告；**先结论后理由**；总长度控制住（这不是覆盖面比赛）。
- 除产出文件外**只读**；可以抽查代码/文档确认，但不必通读。
- 产出写 `docs/reviews/2026-09-15-fable-评审.md`，最后一行打印 `REVIEW DONE <建议条数>/<必须 N 条>`。
