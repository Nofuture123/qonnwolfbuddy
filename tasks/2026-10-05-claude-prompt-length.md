## 0. 原始意图与范围

原始意图（Rocky）：派出去的活要可靠开工；主控和工人不该停在「等人确认」上没人知道。

### 事实（真机实测，Herdr 0.9.3、Claude Code 2.1.289，记录在 `docs/reviews/2026-10-05-claude-code-herdr-probe.md`，先读它）

1. 经 `herdr agent prompt` 或 `herdr pane run` 发给 Claude Code 的文字，只要含换行，或单行超过 800 个字符（按字符数，不按字节），Claude Code 会把它整段记成粘贴内容（`pasted_content`），外面没有使用者自己的文字。786 字符是普通输入，806 字符是粘贴；两条发送通道表现相同。
2. 被记成粘贴之后模型怎么做不固定：两轮演练里多行长指令都被要求「本人确认后才执行」；产品真实的派工提示词（849 字符、单行）那一次直接开工了。也就是说现状靠运气。
3. 本工具里往别的窗口发文字的位置（主控已核对代码，行号为基点处的约数）：`bin/qwb-run.sh` 的执行者派工提示词（约第 725 行组装，第 856、865、886 行发出，返工与续派在前面再加前缀）；`bin/qwb-wake.sh` 约第 859 行（交接门铃，发给主控或常驻职责窗口）与约第 901 行（可见值守叫醒主控的 `看账本：…`，多张票拼成一条）。
4. Pi 没有这个问题；Pi 路径上的文字不要动。

### 要做的事

1. **发给 Claude Code 的每一条文字都是单行且不超过上限。** 上限取 600 个字符（留余量，写成一个有名字的常量并注明来源）。目标窗口运行的是不是 Claude Code，用脚本里已有的信息判断（派工时是工人的 harness；叫醒时读目标窗口的工具种类——先看现有代码已经拿到了什么，不要为此多打一轮 Herdr 查询；确实拿不到工具种类的地方，按 Claude Code 对待，即一律走不超限的写法）。
2. **超限时内容不能丢。** 完整文字落到项目里的文件（放在 `qwbuddy/` 下已有的运行时目录风格里，文件名带操作号或内容摘要，原子写入，不覆盖别的操作的文件），发出去的那一行只指路：说明这是谁发的什么、完整指令在哪个文件、先完整读它再照做。指路行本身要通顺，像人话，不要只甩一个路径。
3. 不超限的文字逐字节照旧发；Pi 目标逐字节照旧发。
4. 留下的指令文件要有清理归属：读代码看 `qwbuddy/` 下同类运行时文件由谁在什么时候清，照同样的规则挂上；没有现成规则就在 `done:` 行说明你选的做法与理由。
5. `templates/` 里若有教主控或常驻职责「往别的窗口发长指令」的句子，补一句同样的规则（单行、不超过上限、长内容放文件）。只加必要的一两句。

白名单：`bin/qwb-run.sh`（仅提示词发出前的整形）、`bin/qwb-wake.sh`（仅两处发出前的整形）、`bin/qwb-lib.sh`（仅新增一个共用的整形函数）、`bin/qwb-worktree.sh`（仅当指令文件的清理要挂在收尾上）、`templates/QWBUDDY.md` 与 `templates/roles/` 下相关的一两句、`tests/` 下为验收所需的已接入文件。
