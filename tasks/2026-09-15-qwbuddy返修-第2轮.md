## R2-M1（必须补）：再次派发会覆盖冻结基线，把改坏的场景洗白

**事实（主控已复现）**：① 首次派发写入 `scenarios-fp: <sha1>`；② 改场景后 lint 正确报 FAIL（rc=1）；③ **再次派发 rc=0**；④ 再 lint → **rc=0 洗白**（基线被新内容覆盖）。另一个退化路径：删掉 `scenarios-fp:` 后保留 `dispatch:`，lint 只提示"旧制派发，无冻结基线"就放过——**新任务丢基线**也被放行。

**规格**：

1. **再次派发不得覆盖已有基线**：
   - 任务书**已有** `scenarios-fp:` 时：重算当前场景块指纹与之比对；
     - **一致** → 正常派发（返工场景合法），**基线原样保留**（不要重写、不要改值）；
     - **不一致** → **拒绝派发**（退出非 0），提示"验收场景在派发后被改动：请恢复场景，或由主控确认后手动删除 `scenarios-fp:` 行再派发"。
   - 任务书**无** `scenarios-fp:` 但**已有** `dispatch:`（曾派发过的新制任务丢了基线）→ **拒绝派发**，提示基线缺失需主控处理；只有显式 `--accept-new-scenarios` 才允许重建基线（并在任务书里留一行说明）。
2. **首次派发**（无基线、无 dispatch）→ 照常写入基线。
3. **负例断言**（三条）：
   - 「改场景 → 再次派发」必须**被拒**；
   - 「未改场景 → 再次派发」必须**成功**且基线**值不变**；
   - 「删基线但保留 dispatch → 派发」必须**被拒**（除非 `--accept-new-scenarios`）。

## R2-M2（必须补）：契约只查「存在且非空」，类型错误能过；坏 fixture 也没喂给真实运行路径

**事实（主控已复现）**：`jpath` 只用 `exists` + `defined` + 非空字符串判断，于是 `pane_id` 为 `{"wrong":1}` / `["audit:p1"]` / `17` / `false` 时 **jpath rc=0**，而运行时会把引用字符串化后传出（`pane=HASH(0x...)`）。另外：坏 fixture 只喂给**测试内的 jpath 函数**，**没有喂给真正的 `qwb-run.sh` 解析路径**——把运行时解析退回旧的全局正则，full 依然 rc=0、241 PASS。

**规格**：

1. **加类型约束**：为契约清单里每个路径声明期望类型（至少：`tab-create` 的 `result.root_pane.pane_id` 必须是**非空字符串**）。`jpath`（或其替代）在类型不符时 **FAIL**：必须拒绝 `HASH`/`ARRAY`/数字/布尔/null/空串。
2. **坏 fixture 必须喂给真实运行路径**：新增断言——用一份**错误层级的 fixture** 驱动**真实的 `qwb-run.sh`**（或直接调它的解析函数），断言：
   - 退出码非 0；
   - **没有继续调用 `herdr agent start`**（用 stub 日志断言）；
   - 没有写入 `dispatch:` 行。
3. **负例断言**：把「pane_id 为对象/数组/数字/布尔」四种错型各断言一次会被拒；并断言运行时解析退化（任意层级正则）会让断言变红——**这条用第 3 步的反转验证证明**，不必固化成断言。

## R2-M3（必须补）：死键判定仍把「名字出现」当「变量被读取」

**事实（主控已复现）**：配置里加 `export QWB_AUDIT_UNUSED=1`，然后把 `bin/helper.sh` 正文分别改成：
- `echo QWB_AUDIT_UNUSED`（只是打印字面量）→ lint **rc=0**（假引用）
- `QWB_AUDIT_UNUSED=2`（只是赋值）→ lint **rc=0**（假引用）
- `echo "$QWB_AUDIT_UNUSED"`（真引用）→ rc=0（正确对照）

**规格**：

1. 死键的"被引用"判定改为**匹配真正的变量引用**：非注释行里出现 `$QWB_X` 或 `${QWB_X}` 才算读取。
2. 明确排除：纯赋值（`QWB_X=...`）、不带 `$` 的字面量（`echo QWB_X`、`echo "QWB_X"`）、注释行。
3. **负例断言**：上面两种假引用各断言一次 `lint` 必须 **rc=1**；真引用对照必须 rc=0。

## R2-M4（必须补，**上一轮最有价值的发现**）：F2 的负例断言是假的

**事实（主控已复现）**：`tests/smoke.sh` 的替身每次注入**同一文本** `done: awk-injected-during-dispatch`，而 `qwb-run.sh` 在**场景提取**阶段就先调用过一次 `awk` → 早就留下了同名标记。于是后面**真的丢行**时，`grep -q` 仍然命中第一次的标记，断言 PASS。审核的反转验证：把实现改回"`agent start` 在前 + `awk` 快照覆盖"的丢行版本，**full 仍 rc=0 / 241 PASS**；独立探针显示 `awk_calls=2` 而 `audit-awk-2` 确实丢了。

**规格**：

1. 替身每次注入**唯一标记**（带序号，如 `done: injected-<N>`），并**记录注入次数**。
2. 断言改为：**所有注入过的标记都必须能在任务书里找到**（个数与内容都对），而不是"存在其一"。
3. **必须做反转验证并贴证据**：把 `qwb-run.sh` 临时改回丢行版本（`agent start` 前置 + `awk` 快照 + `mv` 覆盖）→ 确认新的断言**变红** → 恢复。在 `done:` 里贴出反转前后的原始输出。
4. **负例断言**：把这次反转验证的**机制**固化成断言——即断言"注入次数 == 任务书里对应标记的出现次数"（这样任何丢行都会被抓）。
