## 1. 维护方法

### 何时做：阶段安排，不拦每次提交

- 主控在一个功能阶段完成时明确安排一轮维护，或在发现若干具体遗留后安排一轮。不能只写“有空再做”；决定暂缓时，在现有阶段任务中写明原因和下次检查节点。
- 未开始的维护计划不提前伪装成正在运行的任务。只在实际准备派发时按既有账本流程激活。
- 不在 commit、push、PR 建立、CI 变绿或合并事件上挂自动 garden；本票不添加定时器、后台扫描或常驻 agent。

### 看哪里：已合入的增量，加一个有界历史区域

- 每轮固定已合入的源码基线，优先检查自上轮已覆盖位置以来的改动及直接关联文档。第一次无记录时，由主控指定提交区间或小模块，不默认全仓扫描。
- 为防止旧问题长期遗漏，阶段维护可轮换检查一个明确的小区域；必须事先写入本轮范围，不临场扩成全仓审计。
- 尚未采用、被否决或仍在开发的方案，不作为删主线旧实现的依据；可以收集线索，但独立维护改动基于已经合入的代码。
- 避开已有执行者正在写的文件。必要重叠交主控安排先后，不能暂停全部功能开发来给维护让路。

### 做什么：修复明确的腐烂，不只交问题清单

优先处理错误的开发命令、失效文档链接、相互矛盾的现行说明、已确认无调用且无外部兼容承诺的内部旧实现、可证明等价的重复代码，以及已合入的调试残留。

在本轮白名单和预算内，维护者应实际提交确定的低风险修复；只对不确定、高风险、无关或超预算项记录依据与下一步。不能为了交差制造删除，也不能永远只交一份问题报告。

删除前核对调用关系、配置、动态加载和外部兼容约束；一次搜索无结果不构成充分依据。产品退化按缺陷处理，不改文档或删测试来掩盖。不删除历史决定、有效测试、失败记录、证据、凭据归属不明的数据或他人的未提交成果。

### 产出什么：独立小改动，走原有流程

```text
主控选定已合入基线、维护范围与预算
    → 一个维护执行者定向检查并修复
    → 独立维护分支 / 小 PR
    → 原有审核、受影响验证及必要集成检查
    → 主控按已有授权合入维护产物
```

有 PR 工作流则交独立小 PR；没有 PR 工作流则交等价的独立待合入变更，不强迫项目引入远端平台。推送、开 PR、合并仍遵守已有授权。

维护任务未结束、失败或缺证据，不阻止无关功能 PR 按原流程合并。若发现真实安全、正确性或数据损坏问题，交原缺陷流程判断影响；需要阻断的是该问题影响的交付，不是“garden 没通过”。维护者没有合并或发布否决权。

### 成本与停止条件

- 每轮默认一个维护执行者，复用已有审核能力，不默认增加多模型会审。
- 主控写清可执行的工作预算：限定少量问题的数量，或选择当前工具可观察的时长/token 预算。建议首轮最多处理三个同范围的低风险问题，形成一个主题一致的小改动；这不是脚本硬阈值。
- 不为凑满三个问题而扫描更多目录。没有值得修的内容，记录覆盖范围后正常结束，不建空 PR。
- 预算用完时停止扩大范围，在安全边界保全已验证产物，注明剩余内容。已验证的小改动可以交付，未经验证的部分不能混入或谎称全量完成；再次派发由主控决定，不能自动无限续跑。
- 使用现有快门、定向检查与全门规则。无改动不重跑全套检查；同对象、版本和条件下可信证据可以复用，合入候选变化后补必要验证，不增加 garden 专属测试门。
- 每轮记录基线、实际覆盖范围、处理项、保留项及理由、验证结果、剩余项和下一步即可。只写实际可得的耗时/token，不虚构统计；预算耗尽不能把未覆盖区间记为已维护。

## 2. 验收场景

### user_正常路径_维护产生实际小修复

Given 一个隔离样例包含已合入的改动、由此过期的使用说明，以及能证明不再使用的内部旧帮助函数；主控给定范围和预算
When 按新维护说明安排一名执行者处理
Then 产生独立维护变更，说明与实际行为一致，必要行为验证通过；报告覆盖范围、删除依据和证据，而不是只列问题；真实项目主线不被演练修改。

### user_失败路径_维护失败不阻塞无关功能

Given 独立维护变更检查失败，同时另一个无关功能候选已满足自身要求
When 主控处理两个任务
Then 只对维护任务返修或暂缓，无关功能仍按原流程决定合入；没有新增 garden required check。维护发现真实主线缺陷时，应交原缺陷流程按实际影响处理，不能一律忽略。

### user_正常与失败路径_无修改或预算耗尽

Given 本轮范围没有值得修复的内容，或预算已用完但仍有未覆盖事项
When 维护者结束本轮
Then 前者如实报告后结束、不制造 PR；后者保全已完成且已验证的部分，列出剩余项与覆盖缺口，不无限派生 agent、不声称全仓已清理。

### user_失败路径_拒绝越界与未采用方案清理

Given 某候选文件仍由其他执行者修改，旧 API 存在调用或兼容关系，或清理依据来自尚未合入的方案
When 维护者判断是否删除或改写
Then 不修改该内容、不覆盖他人 WIP；把具体冲突或疑点交主控决定。功能任务无需等待维护扫描完成，清理者不擅自扩大白名单。

### user_失败路径_不能用文档掩盖退化

Given 文档描述的功能按已确认契约应存在，但实际产品行为已经失效
When 维护者核对说明
Then 记录为产品缺陷，不能删除该功能说明、弱化断言或删除测试来制造一致；历史决定、失败记录和原始证据保留。

### user_正常路径_角色可发现并可交接

Given 一个隔离安装副本包含更新后的模板和维护角色，以及上一轮的基线、覆盖范围和剩余项
When 新会话沿 QWBUDDY 入口读取维护方法，现任主控安排下一轮
Then 能从原任务账本恢复范围，不重新全仓扫描；仅当前维护执行者加载详细方法，普通功能任务没有新增必填步骤或门禁。安装验证不得改全局配置或其他真实项目。
