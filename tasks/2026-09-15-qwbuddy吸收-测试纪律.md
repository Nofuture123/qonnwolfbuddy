## 0. 背景与目标

QW buddy 是一个**装进项目的 AI 主控协作层**（不是应用软件）：一份说明书 + 几个 shell 脚本 + markdown 账本。它要解决的问题是「主控叫不醒、没有身份切换、没有派工标准」。

本票吸收五条外部测试原则，**关键要求：必须落成可执行的东西，不能只写进说明书正文**——否则违反原则本身（"能自动检查的规范不要只写在纸上"）。

五项吸收内容 **A / B / C / D** 全做，范围较大，请一次做完再报。

**范围（白名单）**：`bin/`（含新增脚本）、`templates/`、`tests/`（含新增 fixture 目录）、母本仓根新增 `qwb.config.sh`。**不要动 `docs/`**（文档同步由主控做）。

## A（必须）：快门 / 全门 —— `bin/qwb-test.sh`

**动机**：改两行代码不该等半天全套测试。

**规格**：

1. `templates/config.sh` 增加两条门声明（放在超时配置附近，带注释）：

```sh
QWB_GATE_FAST="bash -n bin/*.sh tests/smoke.sh && shellcheck bin/*.sh"
QWB_GATE_FULL="bash tests/smoke.sh && bash bin/qwb-lint.sh"
```

2. 新增 `bin/qwb-test.sh`：

```
用法: qwb-test.sh <fast|full> [--project <根>]
```

- 读配置：优先 `<项目>/qwbuddy/config.sh`，**若不存在则回退 `<项目>/qwb.config.sh`**（母本仓自用，它是模板源，不给自己装一套 `qwbuddy/`）。
- 用 `bash -c "$QWB_GATE_FAST"`（或 `_FULL`）执行，**工作目录 = 项目根**。
- **原样转发**命令输出（stdout + stderr 都要看得见），**退出码透传**。
- 门失败时额外打印一行，格式：`门失败（<fast|full>）：<命令原文> 退出码=<n>`，并写到 **stderr**。
- 未声明对应门时：报错并**打印这段声明的正确写法**（告诉项目该怎么加），退出码非 0。
- `--help`。
- **不得**用 `eval` 之外的方式拼命令；`set -euo pipefail` 下要把失败命令的退出码捕获后再自行决定退出。

3. 母本仓根新增 `qwb.config.sh`（**本仓自用**，声明自己的两条门）：

```sh
# 本仓（QW buddy 母本仓）自己的质量门声明
QWB_GATE_FAST="bash -n bin/*.sh tests/smoke.sh && shellcheck bin/*.sh"
QWB_GATE_FULL="bash tests/smoke.sh && bash bin/qwb-lint.sh"
```

## C（必须）：QW buddy 自己的 lint —— `bin/qwb-lint.sh`

**动机**：能自动检查的规范不要只写在说明书里；且我们已被"写在纸上的规范"坑过两次（当初 DESIGN 承诺的「锁」半年无人发现没实现；worktree 收尾规范写在说明书里而没有任何实现）。

**规格**：新增 `bin/qwb-lint.sh`，`--project <根>`（默认当前目录），逐项检查并输出 `PASS/FAIL`，最后汇总，**任一 FAIL → 退出码 1**。

检查项：

1. **文档承诺的脚本必须存在**：从 `<项目>/qwbuddy/QWBUDDY.md`（以及存在时的 `docs/DESIGN.md`）里提取所有形如 `qwb-*.sh` 的名字，每一个都必须在 `<项目>/qwbuddy/bin/`（母本仓则是 `bin/`）存在。缺失即 FAIL 并列出名字。
2. **账本 state 合法**：`<项目>/tasks/*.md` 里出现的 `state:` 值必须 ∈ `running|blocked|needs-decision|done|verified`；非法值 FAIL 并指出文件名与值。
3. **config 无死键**：配置里每个 `QWB_*` 变量都必须在某个 `bin/*.sh` 里被引用；出现没被引用的键即 FAIL（防"配置写了没人读"）。
4. **无「变量后紧跟非 ASCII」写法**：扫描 `bin/*.sh`，出现 `$VAR` 后紧跟非 ASCII 字符（应写成 `${VAR}`）即 FAIL——这条把错题本里的坑固化成 lint。

要求：纯 shell（可用 `grep`/`sed`/`awk`/`perl`，**不引新依赖**），**不要**在运行时脚本里用 `python3`。

## D（必须）：假替身要有契约基线 + 可注入时钟

**动机**：① 现在的 herdr stub 是硬编码 `echo`，**没有校验它和真实 herdr 的契约**——herdr 换字段名，测试照样绿；② 现在测等待预算只能真 `sleep`，属于"睡几秒再祈祷"。

**规格**：

1. **契约基线**：新增 `tests/fixtures/herdr/`，把**真实 herdr 的响应**存成样本文件（每条命令一个文件），至少覆盖脚本实际依赖的调用：`tab create`、`agent start`、`agent prompt`、`agent wait`、`agent list`、`pane run`。
   - 样本必须是**真实**输出（用 `herdr <cmd>` 在真实会话里录；录不到的场景要在文件头注释说明是构造的**并按真实输出形状**写）。
   - `tests/smoke.sh` 里的 herdr stub 改为**从 fixture 读**（`cat "$FIXTURE"`），不再硬编码 JSON。
2. **契约断言**：smoke 增加一条检查——fixture 里必须存在脚本所依赖的 JSON 字段路径，至少：`.result.root_pane.pane_id`（`tab create`）、`.result.ok` 或存在性（其余）。字段缺失即 FAIL 并指出。
3. **可注入时钟**：`bin/qwb-wake.sh` 的计时与睡眠改为可注入：
   - `now_ms()`：若 `QWB_NOW_MS_CMD` 非空则执行它取毫秒值，否则用现有 `perl -MTime::HiRes` 实现。
   - `sleep_ms()`：若 `QWB_SLEEP_CMD` 非空则执行 `"$QWB_SLEEP_CMD" "$ms"`（把毫秒传给它），否则用现有小数秒 `sleep`。
   - 两个变量**只用于测试注入**，默认行为必须与现在**完全一致**（不得改变默认等待语义）。
4. **smoke 用假时钟测预算**：新增断言——用一个"每次调用递增 N 毫秒"的假时钟 + 立即返回的假 sleep，验证「一轮 = 1×interval」的预算逻辑（**不再真 sleep**）。同时保留一条真时钟的轻量冒烟（真跑一轮即可，不要跑 4 秒）。

## 硬约束（不变）

零通知使用者；无队列/ACK/数据库/守护进程/cron；只用 Herdr；超时一律毫秒；工人禁 headless；**纯 shell 零外部依赖**（`grep/sed/awk/perl/sleep` 可用；**`python3` 只允许出现在 `tests/smoke.sh`**）；变量后紧跟非 ASCII 字符一律 `${VAR}`；**不要用字符串拼接去绕任何断言**（那等于让门失效）。

## 验收门（你必须先自己跑通，主控会独立重跑）

1. 快门：`bash bin/qwb-test.sh fast`（在本仓根跑）→ 退出码 0。
2. 全门：`bash bin/qwb-test.sh full` → 退出码 0，且输出里能看到 lint 的逐项 PASS。
3. `bash tests/smoke.sh` 全过（现有 126 项不许退化），并新增 A/B/C/D 的断言（预计新增 10 项以上）。
4. **假时钟生效证明**：跑一次"全门"，把总耗时与改动前对比贴出来（预期**变快或持平**，不得因为新增断言而显著变慢）。
5. `grep -rn 'python3' bin/` 必须**零命中**（运行时脚本不许用 python3）。

## 报告要求

往主账本绝对路径（本文件）追加状态行 `working:` / `done:`（含跑了什么命令与原始结果）/ `blocked:`。`done:` 里要写明：新增/修改了哪些文件、每种 fixture 是真录还是按形状构造、假时钟注入的实际机制。最后打印 `DONE <commit sha>` 或 `STOP <原因>`。**不要改本文件的 `state:` 字段。**
