# set -e 下函数末尾短路返回值打断主循环

**日期**：2026-09-15
**发现者**：主控独立验收（工人首轮自检未发现；`--once` 单轮效果看起来是对的，掩盖了问题）

## 现象

`qwb-wake.sh`（值守脚本）在**有未结项**时退出码为 1；更严重的是非 `--once` 模式下**主循环第一轮就退出**——值守死了。

而它死去的那一刻，恰好是账本里有未结项、最需要它继续待命的时刻。

## 根因

```bash
check_round() {
  local f st lw need=0 ids=""
  while ...; do ... need=1 ... done
  [[ "$need" -eq 0 && -z "$ids" ]] && echo "账本无未结项"   # ← 有未结项时这行返回 1
}
```

`[[ cond ]] && echo` 在 cond 为假时整体返回 **1**，于是函数返回 1。调用点：

```bash
while :; do
  check_round          # ← set -e 在这里终止整个脚本
  [[ "$ONCE" -eq 1 ]] && exit 0
  wait_round
done
```

`set -e` 遇到非条件上下文中的非零返回值即退出。"函数返回值"也算。

## 对策

1. 函数**显式** `return 0`（别指望最后一行是 0）：

```bash
check_round() {
  ...
  if [[ -z "$ids" ]]; then echo "账本无未结项"; fi
  return 0
}
```

2. 用 if/fi 代替 `[[ cond ]] && action` 表达"可选动作"，尤其在任何 `set -e` 脚本里。
3. 门里加断言：`qwb-wake.sh --once` 在有未结项时**退出码必须为 0**（`tests/smoke.sh` 已加）。

## 教训

`--once` 路径跑一遍看起来一切正常（叫醒动作、wake 行都写了），**单轮成功掩盖了退出码错误**；只有测退出码 + 测主循环是否活着才暴露。

「脚本跑完了」≠「脚本以成功状态结束」≠「脚本会继续活着」。循环类脚本（值守、监听）必须单独验证**循环还能不能转下一轮**，不能只验单轮效果。
