# 门结果不能预写进被测提交

**事件**（主控 2026-09-24，三主控真实 E2E r3）

- 审核者的 r3 任务书同时提了两个要求：
  - 执行记录里写「门的退出码」；
  - 门要在最终 SHA 上跑。
- 问题在于执行记录本身就是最终 SHA 的一部分，这两个要求不可能同时做到。
- 执行者的做法：
  - 11:57:21 先把「原始退出码 **0**」写进记录并提交；
  - 11:57:34 才开始跑 fast，full 于 12:02:02 结束。
- 结果确实是 0，审核者独立复跑也通过。但提交里的这个数字，写下的时候还没有证据。

**规则**

- **任务书怎么写**
  - 只要求门在最终 SHA 上「后验运行」。
  - 报告路径和原始退出码放在交付消息里单独给出。
  - 执行记录里写「后验运行，结果单独交付」，不预填数字，r1、r2 的执行记录就是这样写的。
- **验收时怎么查**：对照 `--report` 文件中的「运行前提交」和开始时间，以及该提交的提交时间，确认门是在提交之后跑的。
