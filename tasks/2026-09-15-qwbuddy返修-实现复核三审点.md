## R1（必须补）：worktree 收尾「有规范、无实现」，且开之前不清点

**事实**：`templates/QWBUDDY.md` §6 写了完整四步规范（含 `archive/<任务id>` 标签、`git worktree prune`），但 `bin/` 里**零实现**；`bin/qwb-run.sh:79-84` 只有 `mkdir -p` + `git worktree add`，没有「先清点」。
**为什么必须补**：`DECISIONS.md` §16 采纳这条规范的目的就是修「废弃工作永远堆积」的死角；「规范写在纸上、靠主控记得」正是本项目要消灭的失败模式。

**规格**：

1. **新增 `bin/qwb-worktree.sh`**，子命令：
   - `list` —— 列出 `<项目>/.worktrees/` 下的目录，并标注哪些是「残留」（该目录对应的任务 id 在账本里**没有未结项**的任务书）与哪些「对应未结项任务」。
   - `finish <任务id> (--merged | --archive | --keep | --keep=<原因>)`：
     - `--merged`：**先核实真的落地**（该分支已合并进当前分支 / 或已推送）→ `git worktree remove` + `git branch -d`；核实不通过则**拒绝**并说明原因（不要盲删）。
     - `--archive`：若工作区有未提交改动，**拒绝**（提示先提交）；否则 `git tag archive/<任务id>` → `git worktree remove` + `git branch -D`。
     - `--keep`：不动 git，只在账本**点名**（把原因写进任务书）。
     - 三种动作都要：操作前检查目标 worktree 有无**未提交改动**（有则拒绝，不做 `--force`），完成后往该任务书追加一行 `worktree: <动作> branch=<...> tag=<...>`，并打印结果。
   - `--help`。
2. **`qwb-run.sh --create-worktree` 之前先清点**：调用 `qwb-worktree.sh list` 的等价逻辑，若发现**残留**目录，打印**警告**（列出残留路径与建议命令），但**不阻塞派发**（使用者可能有意保留）。没有残留则静默通过。
3. `qwb-init.sh` 把新脚本一并复制进 `qwbuddy/bin/`（它已经在用 `qwb-*.sh` 通配，确认覆盖即可）。

## R2（必须补）：`config.json` 里的死配置

**事实**：`templates/config.json:30` 的 `timeouts.agent_wait_ms`（1800000）**没有任何脚本读取**；实际等待上限用的是 `wake_interval_ms`（`bin/qwb-wake.sh:49`）。配置写了没人读 = 配置在撒谎，且 `DESIGN.md` §4.2 举的例正是「30 分钟兜底」，会误导读者以为等待上限是 30 分钟。

**规格**：

1. **删除** `timeouts.agent_wait_ms`（保留 `wake_interval_ms` 与 `agent_start_ms` 两个真正被读的键）。
2. `tests/smoke.sh` 加一条**防死配置**断言：解析 `config.json` 的 `timeouts` 段，每个键名都必须能在 `bin/*.sh` 里找到引用（用 `grep -q` 检查键名），否则 FAIL。这条断言用来防止以后再塞进没人读的配置。

## R3（必须补）：工人名校验是「整文件子串匹配」，等于不校验

**事实**：`bin/qwb-run.sh:59` 用 `grep -q "\"$WORKER\"" "$CONF"`。主控实测：`--worker note`（`note` 只是 `config.json` 里的说明字段名）**通过校验**，herdr 实际收到 `agent start qwb-x --kind note`（非法 kind）。

**规格**：

1. 改为**只在 `workers` 段内、匹配「作为键名出现」**：例如先 `sed -n '/"workers"/,/^  }/p' "$CONF"` 取出该段，再用 `grep -qE "^[[:space:]]*\"${WORKER}\"[[:space:]]*:"` 匹配。
2. 校验失败时，报错信息里**列出当前 config.json 里的合法工人名**。
3. `tests/smoke.sh` 加断言：`--worker note` 必须被**拒绝**（退出码非 0），且不得调用 `herdr agent start`。

## R4（必须补）：`state` 非法值静默漏事

**事实**：主控实测，任务书写 `state: pending`（不在声明的 5 值域内）时：
- `bin/qwb-wake.sh --dry-run` 输出「**账本无未结项**」→ 该任务**永远不会叫醒主控**（漏事）；
- `bin/qwb-status.sh` 对它只显示 `[?]`，无任何提示。

**规格（不新增值域，只让非法值变可见）**：

1. `templates/QWBUDDY.md`：在 §3 或 §1 写明——**任务书写好即写 `state: running`**；「已写好、待派发」不需要单独状态（对值守而言「待派」与「已派」同义：都要主控动手）。值域仍是 5 个。
2. `bin/qwb-status.sh`：未知 state 不再只显示 `[?]`，要显示**醒目的非法标记**，例如 `[非法] state=pending —— 该任务不会被值守叫醒`。
3. `bin/qwb-wake.sh`：扫描时遇到非法 state 值，向 **stderr 警告一行**（不把它算作未结项，但必须说出来），格式如：`警告：<文件名> state=<值> 非法（不在 5 值域内），不会被叫醒`。
4. `tests/smoke.sh` 加断言：
   - `state: pending` 的任务书，`qwb-status.sh` 输出里含「非法」字样；
   - `qwb-wake.sh`（stderr 合并）对同一账本出现「非法」警告。

## 硬约束（不变）

零通知使用者；无队列/ACK/数据库/守护进程/cron；只用 Herdr；超时一律毫秒；工人禁 headless；纯 shell（不引 jq / python 运行时依赖；`python3` 仅允许在 `tests/smoke.sh` 里做 JSON 校验）；变量后紧跟非 ASCII 字符一律 `${VAR}` 花括号。
