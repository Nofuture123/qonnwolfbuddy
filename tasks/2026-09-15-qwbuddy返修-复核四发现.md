## G1（致命）：detached HEAD 下归档/落地对象错位，实际工作丢失引用

**事实（主控已复现）**：worktree 原在分支 `T` 的提交 A，之后 `git checkout --detach` 并产生提交 B，工作区干净、分支 `T` 仍指向 A。此时：
- `finish T --archive` → 退出码 0，但 `git tag archive/T` 打的是**分支 T 指向的 A**，随后 `worktree remove` + `branch -D T` → **B 失去引用**；
- `finish T --merged` → 检查的是 `T`（A）是否已合并，**放行删除实际未合并的 B**；
- 触发条件只是**正常的 detach 操作**，不是恶意输入。

**规格**：

1. 一切判断与归档，一律以 **worktree 当前 HEAD 的实际提交 OID** 为准（`git -C "$WT_DIR" rev-parse HEAD`），**不得**用同名分支当作"该 worktree 的工作"。
2. 用 `git -C "$WT_DIR" rev-parse --abbrev-ref HEAD` 判断是否 detached（返回字面量 `HEAD` 即 detached）。
3. **detached 时**：
   - `--archive`：`git tag archive/<任务id> <HEAD 的 OID>`（不能用分支名）→ `worktree remove`；**不要删那个同名分支**（它指向的是别的东西，不是这个 worktree 的工作），并在输出里说明"保留分支 `<名>`（它不指向本工作区）"。
   - `--merged`：判断 **HEAD OID 是否已合并进主项目 HEAD**（例如 `git merge-base --is-ancestor <OID> <主 HEAD>`），不通过则拒绝。
4. **非 detached 但分支名与目录名不一致**时（例如目录是 `T` 而 HEAD 在分支 `X`），以**实际分支 `X`** 为准，并在输出里显式提示这种不一致。
5. `git status --porcelain` 返回**非 0**（命令失败）时，不得当作"干净"继续（现在的 `|| true` 会静默放行）——应当**拒绝**并报错说明无法确认工作区状态。

## G2（必须补）：并发等待的"最大延迟"是 2×interval，文档写错且实现有重复等待

**事实（主控已复现）**：`wait_round` 在 `herdr agent wait` 因**超时**返回非 0 后，还会再执行一次完整的 `sleep_interval`。interval=1000ms 时实测 5.2 秒内只完成 3 轮等待（≈1.7 秒/轮）。`DESIGN.md` §10 声称"最大延迟 = 1×`wake_interval_ms`"与事实不符。

**规格**：

1. **一轮（wait + 可能的 sleep）的总耗时预算为约 1×`interval`**：等待本身已经耗掉的时间要计入预算，不得重复等待。
2. 具体：`agent wait` 返回后，若它**已经耗掉约 ≥ 半个 interval**（视为超时路径），直接进入下一轮扫描，**不再 sleep**；只有**立即失败**（耗时接近 0，例如 pane 不存在）才 `sleep` 一个间隔，防忙循环。
3. 计时用 `date +%s` 前后差（macOS 的 `date` 不支持 `%N`；bash 内建 `SECONDS` 秒级精度也够用，二者皆可）。
4. 保持原有性质：**任何单次失败都不得让主循环退出**。
5. 效果：默认配置（120000ms）下，并发工人时的最大唤醒延迟回到**约 2 分钟**（1×interval）——主控随后会据此修正 `DESIGN.md` §10。

## G4（可以不要，但与规范冲突，顺手修）：`--keep` 不该被脏检查挡住

**事实（主控已复现）**：`templates/QWBUDDY.md` §6 明确允许「留·例外：有冲突待解的」worktree 保留，但 `qwb-worktree.sh` 的脏检查在动作分流**之前**执行，于是 `--keep` 遇到未跟踪文件或冲突（`UU`）会退出 1，到不了保留记账——把规范允许的场景排除了。

**规格**：脏检查只用于 `--merged` / `--archive`（这两个真的要删东西）；`--keep` **不做**脏检查（它本来就不动 git），照常记账保留。`--keep` 仍必须把原因写进任务书。
