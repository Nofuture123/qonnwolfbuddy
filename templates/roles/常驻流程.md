# 常驻流程：从原话到本地落地

主控、副主控和门控按自己的步骤执行；工人在隔离副本执行。身份来自实际登记，不靠在别人的 shell 里改 `HERDR_PANE_ID`。先读 [总说明](../QWBUDDY.md) 开局及 [收件箱约定](收件箱约定.md)。本文是一个新增 `hello.txt` 的最小完整例子，产品项目替换为自己的需求和质量门。

## 使用前提与可执行标记

- 各 bash 块均在 `set -euo pipefail` 下执行；任意命令失败就停止当前步骤并读回对账，不跳过拒绝继续后续动作。
- 主控已取得锁；项目根是干净的本地 `main`，工具已安装，Git 提交身份已配置。已按 [宿主专项](../host-watch-guide.md) 核实唯一值守；`QWB_WORKSPACE` 指向本项目主 workspace，常驻 Pi 控制确已实测后才配置 `QWB_ROLE_PI_CONTROL=verified`。
- 工人表存在 `pi-sol-high`、`pi-astra-low`。项目的 `QWB_GATE_FULL` 真正检查本文两个场景；演示检查 `hello.txt` 字节恰好为 `hello\n`，错误内容比较必须失败。fast/priority 关闭；不要为运行示例修改真实项目的门。
- `<!-- qwb-walk:步骤 actor=身份 -->` 后的 bash 块是测试原样执行的正常步骤；其中 heredoc 就是完整 JSON 样例。修订分支使用 `qwb-revise:` 同形标记，测试在步骤 04 开票后、05 派工前插入该分支，再继续直到两票 verified。测试从**安装后的文档**取块，不另抄命令；在验门控时发生修订的额外 handoff 仍按文末说明执行。
- 替换表如下。仅替换明确标记；JSON 字符串内用 JSON 转义，shell 单引号内用 shell 转义，JSON 对象标记作为整体替换。实际操作也必须从指定读回结果取值，不能猜。离线测试仅在进程/Herdr边界提供假身份、会话、派工活动及审核结果；票、授权、派发、门收据、Git 快进和收尾全部走真实公开入口。

| 标记 | 取值来源 |
|---|---|
| `@ROOT@` | 项目根的物理绝对路径 |
| `@BASE@` | 派工前 `git rev-parse main` 的完整 OID，保存到主控工作目录 |
| `@INTAKE_SHA@` | 刚写出的来源票的 SHA-256 |
| `@SOURCE_EVENT@` | 步骤 03 的 send stdout（不是自行拼接的 event ID） |
| `@REVISION_EVENT@` | 修订分支 r01 的 send stdout，不能复用原始需求事件 |
| `@IMPL_PANE@` / `@REVIEW_PANE@` | 原票 dispatch/门控子派工记录里的真实 pane |
| `@HEAD@` | 工人交付后候选 `git rev-parse HEAD` 的完整 OID |
| `@CONTEXT@` | 步骤 09 的 gate-context 完整 JSON 对象，保留所有键 |
| `@IMPL_SESSION@` / `@REVIEW_SESSION@` | 两份 Pi 原生 JSONL 的 session.id |
| `@IMPL_NATIVE@` / `@REVIEW_NATIVE@` | 对应 Pi 原生 JSONL 的真实绝对路径 |

操作号在**同一张票**的 claim、dispatch、交接中共享唯一命名空间：本例门控 claim=`gate-hello-1`，交接=`ack-事件ID`，主控接回并落地的 claim=`land-hello-1`。三类不要混用；`land-authorize` 和 `land` 的 op **必须复用主控本人刚取得的 claim**，不是再发明第四个 op。重试既有动作沿原 op，新的交接用新 op。

载荷与结果分别放 `qwbuddy/.roles/controller.work/`、`planner.work/`、`gate.work/`；actor 改名时同步改工作目录。这些是忽略的运行态文件，不进入候选和 tasks。

## 01 主控：启动两个常驻职责，准备来源票

首次启动两者；已存在时先 `qwb-role.sh status --project 项目根` 读回，不重复 start。脚本标识仍叫规划、门禁。本例来源票必须尚不存在；中断后先 read 对账，从未完成的步骤续接，不重写来源票。

<!-- qwb-walk:01-intake actor=controller -->
```bash
cd '@ROOT@'
test ! -e tasks/2026-10-05-intake.md
test ! -L tasks/2026-10-05-intake.md
mkdir -p qwbuddy/.roles/controller.work qwbuddy/.roles/planner.work qwbuddy/.roles/gate.work
bash qwbuddy/bin/qwb-role.sh start --project '@ROOT@' --actor planner --role 规划 --worker pi-astra-low --dir '@ROOT@'
bash qwbuddy/bin/qwb-role.sh start --project '@ROOT@' --actor gate --role 门禁 --worker pi-astra-low --dir '@ROOT@'
git rev-parse main > qwbuddy/.roles/controller.work/base.txt
cat > tasks/2026-10-05-intake.md <<'TASK'
# 需求入口：hello
state: running
## 原始意图
在项目根新增 hello.txt，内容为 hello 和一个换行。
## 工程规格
只登记需求、授权、关联实现票并核对最终交付；本票不派实现工人。
## 必要约束
实现由 hello 工作包承担；本票由主控结案。
## 验收场景
### user_正常路径_需求交付
Given 用户原话已登记
When 实现票落地并清理
Then 原话、实现票和落地提交可追溯
### user_失败路径_未交付不结案
Given 实现票未 verified
When 检查来源票
Then 拒绝把来源票置为 verified
TASK
shasum -a 256 tasks/2026-10-05-intake.md
```

完成标准：两个角色登记有真实会话，来源票只有正文、没有旧写入者。新票不需要虚构停止过程；下面七项明确说明新票的真实状态。已有票必须逐项停写、关闭旧 FD、核对外部动作后填写真实证据。

## 02 主控：受控迁移，办理迁入核查

<!-- qwb-walk:02-migrate actor=controller -->
```bash
cd '@ROOT@'
cat > qwbuddy/.roles/controller.work/migrate.json <<'JSON'
{
  "task_sha256": "@INTAKE_SHA@",
  "confirm": {
    "run": "本票刚新建，尚未派发，run 未写过本票",
    "wake": "本票新建期间尚未交给值守，已核对无本票在途写入",
    "worktree": "本票不派实现，尚无本票副本或收尾动作",
    "worker": "本票无工人，无工人写入",
    "controller": "主控已结束本票正文写入，持锁准备单票迁移",
    "old-fds": "正文写入已关闭，已核对无旧写 FD",
    "external-actions": "仅新建本票，未执行外部交付动作"
  }
}
JSON
bash qwbuddy/bin/qwb-ledger.sh migrate --project '@ROOT@' --task tasks/2026-10-05-intake.md -- qwbuddy/.roles/controller.work/migrate.json
bash qwbuddy/bin/qwb-send.sh pending --project '@ROOT@' --task tasks/2026-10-05-intake.md > qwbuddy/.roles/controller.work/intake-pending.json
```

迁移自动生成给主控的「迁入核查」交接。先读上一步 pending 的完整 payload，核对确实没有旧义务，再运行下面的办理命令。本例保存一个只做四步收据的 shell 函数，后续复用；它不能替你验证 evidence 的真实性，不能盲目对未知待办批量办结。

<!-- qwb-walk:02-ack actor=controller -->
```bash
cd '@ROOT@'
cat > qwbuddy/.roles/controller.work/ack.sh <<'SH'
ack() {
  local task="$1" event="$2" work="$3" evidence="$4" op="ack-$2"
  bash qwbuddy/bin/qwb-send.sh received --project "$PWD" --task "$task" --event "$event" || return
  bash qwbuddy/bin/qwb-send.sh accept --project "$PWD" --task "$task" --event "$event" --op "$op" || return
  bash qwbuddy/bin/qwb-send.sh prepared --project "$PWD" --task "$task" --event "$event" --op "$op" || return
  python3 - "$event" "$op" "$evidence" "$work/result-$op.json" <<'PY'
import json, sys
from pathlib import Path
Path(sys.argv[4]).write_text(json.dumps({"event_id": sys.argv[1], "op_id": sys.argv[2], "outcome": "applied", "evidence": sys.argv[3]}, ensure_ascii=False) + '\n')
PY
  bash qwbuddy/bin/qwb-send.sh handled --project "$PWD" --task "$task" --event "$event" --op "$op" --result-ref "$work/result-$op.json"
}
SH
. qwbuddy/.roles/controller.work/ack.sh
migration_event="$(python3 -c 'import json; a=json.load(open("qwbuddy/.roles/controller.work/intake-pending.json")); assert len(a)==1; print(a[0]["event_id"])')"
ack tasks/2026-10-05-intake.md "$migration_event" qwbuddy/.roles/controller.work '已读迁入原文；新票无旧工人、FD或外部待办'
```

`handled` JSON 严格只有 `event_id/op_id/outcome/evidence`；outcome 为 `applied` 或 `not-applied`。失败/未知不得写成 handled。此时来源票迁入核查已办，下一步登记原话。

## 03 主控：登记原话，授予副主控范围

<!-- qwb-walk:03-source actor=controller -->
```bash
cd '@ROOT@'
bash qwbuddy/bin/qwb-send.sh send --project '@ROOT@' --task tasks/2026-10-05-intake.md --corr hello-request --attempt 1 --text '在项目根新增 hello.txt，内容为 hello 和一个换行。' > qwbuddy/.roles/controller.work/source-event.txt
```

<!-- qwb-walk:03-assign actor=controller -->
```bash
cd '@ROOT@'
cat > qwbuddy/.roles/controller.work/plan-assign.json <<'JSON'
{
  "request_id": "hello-request",
  "source_event": "@SOURCE_EVENT@",
  "packages": {"hello": "2026-10-05-hello.md"},
  "paths": ["hello.txt"],
  "workers": ["pi-sol-high"],
  "permissions": ["new", "dispatch"],
  "evidence": "用户已授权新增 hello.txt；主控授予这个工作包一次实施启动，不含发布或付费操作",
  "budget": 1
}
JSON
bash qwbuddy/bin/qwb-ledger.sh plan-assign --project '@ROOT@' --task tasks/2026-10-05-intake.md -- planner qwbuddy/.roles/controller.work/plan-assign.json
```

字段契约：`request_id` 是稳定 ID 字符串；`source_event` 必须是该入口票真实 send 事件；`packages` 是包 ID→**文件名**对象，1–64 项，文件名只能含 ASCII 字母数字、`_ . -` 且以 `.md` 结尾，不能写 `tasks/`；`paths` 是字符串数组，元素非空且不重复（推荐精确相对路径）；`workers` 为非空具名工人数组，不能 auto；`permissions` 为不重复字符串数组、元素非空，**代码无枚举限制且允许空数组**，推荐 `["new","dispatch"]`，这些词不新增权限；`evidence` 为非空真实授权依据字符串；`budget` 推荐 JSON 整数 1–64，是**每张票每个 spec_rev 的启动次数上限**，不是按票映射。ID 使用 ASCII 字母数字与 `_ . : -`，最长160字符。

成功后 planning_authority 绑定本代 planner。主控**不要自行 received/handled 原话**；结束回合，唯一值守按该来源自动叫副主控。不要手写 inbox、直接打字或自己轮询 qwb-wake。主控授权产生的普通 working 不代替副主控办理需求。

## 04 副主控：接原话，new 开实现票

先完整读 pending 中该事件，再 received→accept→prepared；`new` 成功后读回，最后 handled。

<!-- qwb-walk:04-new actor=planner -->
```bash
cd '@ROOT@'
bash qwbuddy/bin/qwb-send.sh pending --project '@ROOT@' --task tasks/2026-10-05-intake.md
bash qwbuddy/bin/qwb-send.sh received --project '@ROOT@' --task tasks/2026-10-05-intake.md --event '@SOURCE_EVENT@'
bash qwbuddy/bin/qwb-send.sh accept --project '@ROOT@' --task tasks/2026-10-05-intake.md --event '@SOURCE_EVENT@' --op plan-hello
bash qwbuddy/bin/qwb-send.sh prepared --project '@ROOT@' --task tasks/2026-10-05-intake.md --event '@SOURCE_EVENT@' --op plan-hello
cat > qwbuddy/.roles/planner.work/new.json <<'JSON'
{
  "request_id": "hello-request",
  "package_id": "hello",
  "packages": {"hello": "2026-10-05-hello.md"},
  "source_task": "2026-10-05-intake.md",
  "source_event": "@SOURCE_EVENT@",
  "intent": "按原话交付 hello 文件",
  "spec": "新增 hello.txt，UTF-8 字节恰好为 hello 加一个换行；提交后报告完整 OID，工作副本干净。",
  "constraints": "只改 hello.txt，不发布、不购买服务，不改主账本 state；提交实现后 append done 到主账本。",
  "scenarios": "## 验收场景\n### user_hello\nGiven 已提交候选\nWhen 读取 hello.txt\nThen 字节恰好为 hello 加一个换行\n### user_reject\nGiven 错误内容\nWhen 与期望字节比较\nThen 拒绝将错误内容认作通过",
  "paths": ["hello.txt"],
  "needs": {"start": [], "accept": [], "land": []}
}
JSON
bash qwbuddy/bin/qwb-ledger.sh new --project '@ROOT@' --task tasks/2026-10-05-hello.md -- qwbuddy/.roles/planner.work/new.json
bash qwbuddy/bin/qwb-ledger.sh read --project '@ROOT@' --task tasks/2026-10-05-hello.md > qwbuddy/.roles/planner.work/new-result.json
cat > qwbuddy/.roles/planner.work/created.json <<'JSON'
{"event_id":"@SOURCE_EVENT@","op_id":"plan-hello","outcome":"applied","evidence":"new-result.json 已读回：hello-request/hello 唯一映射到 2026-10-05-hello.md，原话及范围一致"}
JSON
bash qwbuddy/bin/qwb-send.sh handled --project '@ROOT@' --task tasks/2026-10-05-intake.md --event '@SOURCE_EVENT@' --op plan-hello --result-ref qwbuddy/.roles/planner.work/created.json
```

场景标题一律 `### user_名字`，Given/When/Then 必须可验证，至少一条失败路径。needs 三个数组必填；有依赖时每条写 `task/artifact/version/spec_rev/condition`，条件为 available/accepted/landed，引用精确文件名和版本。未知/中断先 read 对账，重放同一 new JSON，不能换文件名再造一票。

成功后来源原话 handled；writer 自动生成 `source:planner-result:` 上行，唯一值守叫主控读回创建结果。副主控可继续下一步，不等主控替自己派发。

## 05 副主控派工；工人提交并交付

<!-- qwb-walk:05-dispatch actor=planner -->
```bash
cd '@ROOT@'
bash qwbuddy/bin/qwb-ledger.sh start-check --project '@ROOT@' --task tasks/2026-10-05-hello.md -- pi-sol-high
bash qwbuddy/bin/qwb-run.sh --project '@ROOT@' --task 2026-10-05-hello --worker pi-sol-high
```

看到 ready、dispatch、真实开工绑定才算派发；默认创建 `.worktrees/hello/` 并登记 Space。工人读取主账本后执行自己的实现与检查。本例工人步骤如下（实际项目由工人实现，不由主控代写）：

<!-- qwb-walk:06-worker actor=worker -->
```bash
cd '@ROOT@/.worktrees/hello'
printf 'hello\n' > hello.txt
python3 -c 'from pathlib import Path; expected=b"hello\n"; assert Path("hello.txt").read_bytes()==expected; assert b"wrong\n"!=expected'
git add hello.txt
git commit -m 'Add hello file'
test -z "$(git status --porcelain)"
head="$(git rev-parse HEAD)"
bash '@ROOT@/qwbuddy/bin/qwb-ledger.sh' append --project '@ROOT@' --task '@ROOT@/tasks/2026-10-05-hello.md' -- "done: 提交 ${head}；python3 字节及错误内容检查通过，工作区干净"
```

工人 done 自动路由主控安排门控；副主控不能替主控办理 done。工人不改 state。账本在主项目，候选只提交产品改动。

## 07 主控核交付，授权门控

先读来源票的副主控结果、实现票的 done 和 dispatch，核查候选位置、提交号、clean、原始 base、范围及两条场景。下面 ack 循环仅适用于本例已经逐条核实的创建结果、授权记录及工人交付；真实票有未知请求/问题时保留并处理，不能照抄批量销账。

<!-- qwb-walk:07-readback actor=controller -->
```bash
cd '@ROOT@'
bash qwbuddy/bin/qwb-ledger.sh read --project '@ROOT@' --task tasks/2026-10-05-hello.md
candidate='@ROOT@/.worktrees/hello'
test "$(git -C "$candidate" rev-parse HEAD)" = '@HEAD@'
test -z "$(git -C "$candidate" status --porcelain)"
git -C "$candidate" diff --stat '@BASE@' '@HEAD@'
. qwbuddy/.roles/controller.work/ack.sh
for task in tasks/2026-10-05-intake.md tasks/2026-10-05-hello.md; do
  bash qwbuddy/bin/qwb-send.sh pending --project '@ROOT@' --task "$task" > qwbuddy/.roles/controller.work/pending.json
  for event in $(python3 -c 'import json; print("\n".join(h["event_id"] for h in json.load(open("qwbuddy/.roles/controller.work/pending.json"))))'); do
    ack "$task" "$event" qwbuddy/.roles/controller.work '已逐项读回副主控结果与工人交付，候选提交、范围和 clean 已核对，下一步授权门控'
  done
 done
cat > qwbuddy/.roles/controller.work/environment.json <<'JSON'
{"external_dependencies":[],"note":"本例仅本地 hello.txt 字节检查，无候选外服务或数据依赖"}
JSON
cat > qwbuddy/.roles/controller.work/gate-assign.json <<'JSON'
{
  "candidate": "@ROOT@/.worktrees/hello",
  "base": "@BASE@",
  "attempt": "1",
  "policy": "qwb-v1",
  "environment": "@ROOT@/qwbuddy/.roles/controller.work/environment.json",
  "required": {"full": ["user_hello", "user_reject"]},
  "workers": {"review": "pi-astra-low", "rework": "pi-sol-high"}
}
JSON
bash qwbuddy/bin/qwb-ledger.sh gate-assign --project '@ROOT@' --task tasks/2026-10-05-hello.md -- gate qwbuddy/.roles/controller.work/gate-assign.json
```

`workers` 只能有 `review/rework`，两者填已配置具名工人；型号与 effort 绑定后不得换。`required` 键只能 fast/full，必须有 full，所有映射的**并集**覆盖全部冻结 `user_` 场景；推荐像样例一样 full 全覆盖。`environment` 是**已存在的候选外文件路径**，不是内联对象；代码摘要文件字节，不规定内容 schema。真实项目应列外部服务/数据/工具依赖的版本、地址或证据引用，不能含秘密，也不能虚构「无依赖」。门控收据另绑定配置、实际工具及选定环境变量。

`base` 是实现开始的完整基点 OID；`candidate` 为真实干净副本；`attempt/policy` 为 ID 字符串。policy 应引用项目当前测试策略；本例写 qwb-v1，若票有 `test-policy:` 头，必须同值并存在 `qwbuddy/test-policy/qwb-v1.md`，还需 `risk: normal|high`。没有该头的旧模式仍绑定 policy 字符串，但不自动启用版本化策略路由。

成功后门控授权进入待接手状态，唯一值守自动叫 gate。主控结束回合，门控按 [门禁](门禁.md) 办理，不手工投 inbox。

## 08–10 门控：claim、独立审核、全门、通过与交还

先 claim，再消费本票交接；长检查保留 claim，必要时 activity 登记有界等待。下面省时的演示也真实派出审核工人；审核工人只读候选，不改产品文件。

<!-- qwb-walk:08-gate actor=gate -->
```bash
cd '@ROOT@'
bash qwbuddy/bin/qwb-ledger.sh claim --project '@ROOT@' --task tasks/2026-10-05-hello.md -- gate-hello-1
bash qwbuddy/bin/qwb-send.sh pending --project '@ROOT@' --task tasks/2026-10-05-hello.md > qwbuddy/.roles/gate.work/pending.json
. qwbuddy/.roles/controller.work/ack.sh
for event in $(python3 -c 'import json; print("\n".join(h["event_id"] for h in json.load(open("qwbuddy/.roles/gate.work/pending.json"))))'); do
  ack tasks/2026-10-05-hello.md "$event" qwbuddy/.roles/gate.work '已读授权与固定候选；本代门控已持 gate-hello-1，承担独立审核及全门'
done
bash qwbuddy/bin/qwb-ledger.sh gate-diff --project '@ROOT@' --task tasks/2026-10-05-hello.md -- gate-hello-1 > qwbuddy/.roles/gate.work/diff.json
bash qwbuddy/bin/qwb-run.sh --project '@ROOT@' --task 2026-10-05-hello --gate-op gate-hello-1 --gate-kind review --name qwb-hello-review --worktree '@ROOT@/.worktrees/hello' --worker pi-astra-low
```

## 规格或场景修订：原票持久请求，CAS 应用，再明确授权

带规划授权的实现票不由主控直接 `revise-scenarios`。以下示例是在步骤 04 开票后、05 派工前收到「明确 UTF-8 字节与一个换行」的补充要求，仍属 hello 包原范围；没有补充要求时跳过本节。真实修订应填写真实原话及完整新规格，不用样例原话冒充用户授权。

主控在承载请求的来源票上 send。成功后原话保留、唯一值守叫副主控；主控不替它办理。
