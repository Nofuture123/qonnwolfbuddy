# CI 与测试效率专项

**触发**：修改 CI／测试门、分析超时或非绿运行、决定是否复用测试收据时，从 [总说明](QWBUDDY.md) §6 进入。普通任务只遵守总说明的场景、快门和验收要求。

CI 是交付门禁。每次 push 尽快给出真实结论，不放宽标准换速度。

1. **同机互斥**：执行者只跑定向测试或快门。全门由主控在合并前跑一次；同机 CI 正在跑时等它结束，避免测试框架 worker 与多会话叠加负载。
2. **超时取证**：提高 timeout、加 retry、关测试隔离只是临时取证，不算修复。验收记录单独计数「首次失败后成功」的用例。先找真等待；虚拟时钟的 now 与 sleep 同步推进，本仓可用 `QWB_NOW_MS_CMD` / `QWB_SLEEP_CMD` 注入。
3. **非绿分类**：每个非绿 run 只归一类：被新 push 取代、job 超时、真实测试失败、重试后变绿。当前配置没有有效记录就标缺证，不拿其他分支或机器代替。
4. **先量再动**：CI／门禁改动前，用真实记录建立步骤／文件耗时基线，分清排队、执行和重跑时间。
5. **共享机器**：不在共享或开发者机器加防火墙、改整机网络或动系统服务。确需改 runner 的真机步骤结束后亲自核残留为零，不采信执行者回执。

门禁去重仅适用于同代码版本、同命令且有可信收据的重复执行。最终交付需验证实际合并版本；`qwb-test.sh --report` 仅证明报告中的一次执行，不能自动 `verified`。
